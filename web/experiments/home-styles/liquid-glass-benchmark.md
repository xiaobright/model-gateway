# 液态玻璃主页实验与性能对比

实验对照版本：`90a5f475662444200ea85863462a14d2b8b7ed3d`，实验时已推送并核对 `origin/master`。以下为 2026-10-02 的测量记录，不代表后续版本的重新测量结果。

实验入口：[液态玻璃主页](liquid-glass-lab.html)。网关运行时可打开 <http://127.0.0.1:8317/static/experiments/home-styles/liquid-glass-lab.html>，也可以直接打开 HTML 文件。单文件、无第三方依赖、无网络请求；所有模型和用量都是演示数据，操作只改变页面内存。

## 视觉实现

- WebGL 2 先生成动态环境纹理，再按 DOM 面板的位置与圆角计算玻璃曲面。
- 曲面法线决定采样偏移，形成边缘折射、内部放大、透射和高光；极致档增加 RGB 色散并提高内部渲染分辨率。
- 鼠标影响高光方向，点击触发短暂的表面波纹。深浅色、搜索、接口筛选、模型选择、首选切换、演示新增模型均可操作。
- DOM 文字保持清晰；折射对象是生成的环境层。这不是对任意网页内容的实时截图折射，也不是路径追踪或真实流体仿真。
- 底部可以选择 CSS 玻璃、液态均衡、液态极致；光学面板可调整折射强度、厚度，并自行测量 12 秒。
- 极致档 DPR 上限 1.75，内部像素数上限 700 万。均衡档 DPR 上限 1；没有自动切低画质掩盖测试结果。

## 实测环境与方法

2026-10-02，本机 Ryzen 9 7945HX、32 GB 内存、RTX 4060 Laptop GPU（8 GB，驱动 610.62），显示器 2560×1600 / 240 Hz。

浏览器为 Codex 内置 Chromium，WebGL 报告 ANGLE / NVIDIA RTX 4060 / Direct3D 11，并支持 `EXT_disjoint_timer_query_webgl2`。本轮确实使用硬件 GPU，没有用软件渲染结果代替。

使用同一个可见标签页、浅色、环境持续流动，每个配置采样约 12 秒。现版通过 `dev/preview-workbench.py` 的独立数据库与模拟上游运行，标准动效开启。实验页使用自己的演示数据；均为九个模型，但不是完全相同的应用负载。原始结果见 [liquid-glass-benchmark.json](liquid-glass-benchmark.json)。

两组视口：

1. 1280×720 CSS 像素，DPR 1.5，浏览器输出约 1920×1080。
2. 1706×1066 CSS 像素，DPR 1.5，浏览器输出约 2559×1599，接近本机屏幕分辨率。此组 DPR 通过开发者工具显式设置。

动画回调频率和间隔由相同的临时 `requestAnimationFrame` 探针记录；主线程忙碌比例是 CDP `TaskDuration` 增量除以采样时长，不是整机 CPU 百分比。GPU 时间是异步 GPU 查询得到的 WebGL 两个绘制阶段的中位数，不包含浏览器最终合成、DOM 绘制和屏幕呈现。

## 结果

| 输出尺寸 | 页面 / 档位 | 动画回调 / 秒 | P95 回调间隔 | 主线程忙碌比例 | WebGL GPU / 帧 |
|---|---|---:|---:|---:|---:|
| 约 1920×1080 | 现版标准玻璃 | 239.0 | 4.3 ms | 9.55% | 不适用 |
| 约 1920×1080 | 实验 CSS 玻璃 | 237.6 | 4.3 ms | 7.55% | 不作比较 |
| 约 1920×1080 | 液态均衡 | 239.4 | 4.3 ms | 7.53% | 0.21 ms |
| 约 1920×1080 | 液态极致 | 238.9 | 4.3 ms | 7.48% | 0.42 ms |
| 约 2559×1599 | 现版标准玻璃 | 239.4 | 4.3 ms | 9.40% | 不适用 |
| 约 2559×1599 | 实验 CSS 玻璃 | 234.0 | 4.3 ms | 7.44% | 不作比较 |
| 约 2559×1599 | 液态均衡 | 239.3 | 4.3 ms | 7.67% | 0.34 ms |
| 约 2559×1599 | 液态极致 | 238.5 | 4.3 ms | 7.80% | 1.00 ms |

八次采样均没有超过 25 ms 的回调间隔。均衡档内部纹理分别为 1280×720、1706×1066；极致档分别为 1920×1080、2559×1599。CSS 对照仍由 WebGL 生成相同环境，但玻璃交给 CSS；其 GPU 查询只覆盖背景生成，不包含 CSS 模糊，因此不能把 JSON 中较小的 GPU 数值当作整页 GPU 成本。

另外验证页面自带的测量按钮时，性能面板保持打开，并有浏览器工具等待操作：12 秒结果为 235.8 次回调/秒、3 个超过 25 ms 的间隔、GPU 中位数 0.83 ms。此场景不同于上述静置对照，单独保存在原始文件的 `selfTestPanel` 中；也说明短测不能保证永不掉帧。

这些数字表示短时间内动画调度和绘制有余量，**不是对实际屏幕呈现帧率、整机耗电或长期温度的保证**。主线程差异也不能直接推导成重写后更省 CPU：页面内容、DOM 和轮询工作不同，而且每档只测了一次。

## 使用建议与边界

这台电脑插电时可以直接体验极致档。在接近整屏输出的采样中，极致档的 GPU 绘制成本约为均衡档的三倍；两者都没有耗尽 240 Hz 的 4.17 ms 帧预算，但最终合成和其他应用仍需共享 GPU。

希望长期打开、降低 GPU 持续工作量时，可选均衡档或暂停环境流动。暂停后只因交互和布局改变重绘；页面隐藏停止帧循环，系统减少动态效果也会停止环境动画。GPU 不可用或上下文丢失时回退到 CSS。缓冲纹理本身在 2559×1599 / RGBA8 下约 15.6 MiB，不能视为总显存占用。

没有测试电池续航、持续温升、独显与核显切换、其他浏览器或真实手机 GPU。手机尺寸检查只验证布局。本实验未接入真实网关业务，也没有替换正式主页。

浏览器另确认：暂停后的帧队列归零且搜索仍能重绘；系统减少动态效果生效；模拟 GPU 上下文丢失后显示 CSS 回退，恢复后重新编译着色器并继续绘制。着色器通过首帧检查，兼容本机 ANGLE / D3D11 对显式浮点构造的要求。
