模型路由

点候选圆片即把该模型切到那一条（高亮的是当前生效的，也是自动降级的起点）。 同一个分组下可以挂好几条，各指一个不同的上游真名。 圆片从左到右就是依次尝试的顺序，在圆片的 ✎ 里调。切换只影响新请求，进行中的流会走完旧上游。

编排

每个大气泡是一个下游模型（一个「模型名 + 接口」= 一条链）。 绕着它一圈的小圆片是它的候选，顺时针方向就是自动降级的尝试顺序； 指针指向的那条是当前实际会先打的，端口上的数字是顺序。 指针可以拨（拖动针尖那个圆点旋转），指到哪条就切到哪条，自动降级也是这根指针自己转过去。 从左边的上游池拖一个模型到气泡上就连上一条候选（拖断不会删，要用端口右键菜单里的「移除」）。 上游节点是参考层，排在气泡左边，按住空白处可以平移画布、滚轮缩放。

实时请求

每条请求一张卡：现在打的是哪个上游、卡在连接还是在等模型出字、已经等了多久， 以及它前面被哪几个候选拒过 —— 那几次失败客户端看不见，但钱是真花了。结束的请求会再留 90 秒，不然降级轨迹只在活着的那几秒里存在，最想看的东西最看不到。 count_tokens（Claude Code 用它算上下文占用）也列出来，但不计入「进行中」。

分组健康

同一个分组连续失败 2 次就冷却 90 秒，再失败翻倍、封顶 10 分钟；冷却期内自动降级 跳过它。手动点圆片切过去照样立刻生效，而且会清掉冷却。这些状态只在内存里，重启就清零。

上游站点

一个供应商 = 一个站（一个站根地址，不带 /v1）。同一个站的多把 key、 以及每种接口（Anthropic Messages / OpenAI Responses / Chat Completions），都是它下面的分组：接口、key、模型列表都在分组上 —— 点一行的空白处展开看，或者进「编辑」里改。

批量添加新模型

填一个模型名，先看哪些上游站有它：完全同名的默认勾上，只沾一部分的排后面、 默认不勾 —— 上游的 id 往往带日期后缀或厂商前缀，得自己认一下再用。 勾中即意味着两件事一起做：把这个站登记进上游模型目录，并在「模型路由」里建一条候选。

搜索上游

Codex 的联网搜索（/v1/alpha/search）默认跟着模型的候选链走。这里可以单独 指定一个 OpenAI 分组专门做搜索 —— 有些站搜索能用但普通模型不通，或者只有某个 分组带搜索权限。只影响搜索，不影响普通对话。

整条链交给…

转发是同接口内的：目标必须在同一个接口下有可用候选，否则转过去也是 404。 设置后自己这条链的候选不参与路由（配置留着，取消转发就恢复）。
