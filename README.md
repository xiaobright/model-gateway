# Model Gateway

把多个 AI 服务接到一个本机地址。客户端只配一次，以后换站点、换密钥、换实际使用的模型，都可以在管理页里操作。

它主要帮你做三件事：

- **集中管理**不同站点的地址、密钥和模型。
- **随时切换**某个模型用哪个站点；已经在输出的回复不会因为切换而中断。
- **看清问题**：请求发给了谁、等了多久、有没有正常结束，必要时手动停止。

它不提供模型，也不负责购买额度。**目前不做接口格式转换**：客户端用哪种接口，选中的站点就必须支持哪种接口。以前试过转换方案，后来已移除。

## 开始使用

### 1. 启动网关

**已经装好环境：**双击 `start-gateway.bat`。它会启动网关并打开管理页：

[http://127.0.0.1:8317/](http://127.0.0.1:8317/)

Windows 右下角会出现托盘图标，可以右键打开管理页、设置开机自启或退出。关闭网页不会关闭网关。

**第一次安装：**先装好 Python 和 uv，在项目目录打开 PowerShell，执行：

```powershell
uv venv .venv
uv pip install --python '.\.venv\Scripts\python.exe' -r requirements.txt
```

已有 `.venv` 时跳过第一条，不要为了更新依赖重建环境。安装完成后再双击启动文件。

如果启动失败，想直接看报错，可在 PowerShell 里运行：

```powershell
& '.\.venv\Scripts\python.exe' main.py --no-tray
```

这个模式下手动打开上面的管理页地址；退出时按 `Ctrl+C`。Linux/macOS 也使用 `--no-tray`，解释器路径改为 `.venv/bin/python`。

### 2. 添加一个站点和密钥

1. 打开「上游站点」，点「添加供应商」。
2. 填名称和站点地址，例如 `https://api.example.com`。**地址末尾不要带 `/v1`**，网关会按接口补齐；粘贴时带了也会自动去掉。
3. 保存后会打开分组编辑框。选接口，填这个站点给你的真实 API Key，再保存。
4. 点「拉取模型列表」，勾选要登记的模型；列表里没有的也可以手动填。

接口按客户端要求选择，不是按模型名字猜：

| 客户端使用的接口 | 分组里选什么 |
| --- | --- |
| Codex 的 Responses 接口 | OpenAI Responses |
| OpenAI SDK、opencode 等配置为 Chat Completions 时 | OpenAI Chat Completions |
| Claude Code 的 Messages 接口 | Anthropic Messages |

**勾选模型立即生效；组名、接口和 Key 要点保存。** 关闭弹窗不会撤销已经勾选的模型。

### 3. 让客户端能选到这个模型

上一步只是记下「这个站点有哪些模型」，**还没有把它加入客户端可用的列表**。

去「模型路由」点「新增模型」：

1. 起一个给客户端用的模型名。
2. 选择接口、供应商和分组。
3. 选择或填写「上游那边的真实模型名」。

例如，你给客户端起名 `my-chat`，实际指向某个站点的 `provider-model`。这两个只是示例名，后者必须换成站点真实支持的名字。
以后想换站点，只需要给 `my-chat` 添加另一个候选并切换，客户端仍然用 `my-chat`。

### 4. 接入客户端

管理页侧栏的「下游接入」可以查看、复制接入信息。

| 用途 | 客户端填写的 API 地址 |
| --- | --- |
| OpenAI Responses / Chat Completions | `http://127.0.0.1:8317/v1` |
| Claude Code（`ANTHROPIC_BASE_URL`） | `http://127.0.0.1:8317` |

- **模型名**：填「模型路由」里自己起的名字。
- **API Key**：通常填任意非空占位值，例如 `local-only`。真正的站点密钥已经存在分组里，网关转发时会使用它。
- **Claude Code 的地址不要加 `/v1`**，它会自己补接口路径。

如果有意把分组 Key 留空，网关会转发客户端带来的鉴权信息；这时占位值不一定能用。

Claude Code 的不同模型档位可以分别指定模型，具体环境变量见[维护说明里的配置示例](dev/maintenance.md#claude-code-配置)。模型在网关里的名字不代表实际价格，费用取决于最终调用的站点和真实模型。

## 几个页面用词

| 页面上的词 | 实际意思 |
| --- | --- |
| 上游、供应商 | 真正提供 AI 服务的站点。一个供应商保存一个地址。 |
| 下游、客户端 | 通过本项目调用 AI 的软件，例如 Codex、Claude Code、opencode。 |
| 分组 | 一把密钥配一种接口。同一个站有多把密钥，或同一把密钥支持多种接口，就分开建组。 |
| 接口、协议 | 软件之间收发请求的格式。Responses、Chat Completions、Messages 不能直接混用。 |
| 候选 | 某个模型的一种调用选择：用哪个分组、调用那个站上的哪个模型。模型下方的圆片就是候选。 |
| 上游模型目录 | 记下某个分组有哪些模型，供配置时选择。 |
| 对下游暴露 | 把模型放进客户端可用的列表，也就是在「模型路由」里配置它。 |
| 出口 | 连接这个站点时，是直连还是经过代理。 |

同一个模型名目前只能属于一种接口。确实要分别用于两种接口时，请起两个不同的名字。

## 日常操作

### 换站点或添加备用

在「模型路由」里点击候选圆片即可切换，高亮圆片表示当前使用的候选。**新请求会使用新选择；已经开始的回复继续完成。**

一个模型可以有多个候选，也可以在同一个分组里配置不同的上游模型名。需要修改、调整顺序时，把鼠标移到圆片上，点编辑按钮。

同一个站有另一把 Key，不必再建供应商，在该供应商里「添加分组」即可。同一把 Key 需要用于另一种接口时，可用「复制这把 key 到 …」，再确认对应模型配置。

### 请求失败时自动换一个候选

界面把它叫作「自动降级」，**意思是失败时换候选，不是自动降低模型档次**。

- Anthropic 默认开启；OpenAI Responses 和 Chat Completions 默认关闭。已有保存设置优先。
- 开启后，会按候选顺序把配置的候选依次试过去，直到成功或试完。不同候选的价格可能不同，请先确认。
- 已经开始输出、带有某些会话状态字段的请求不能换候选；上游说请求有问题（400/422）会继续试下一个候选，但不记这个站的故障。
- 「同站重试」是另一个设置：先在原站再试，次数用完后才考虑换候选。没配置规则就不会启用。

具体状态码和例外见[重试规则](dev/maintenance.md#重试与自动换候选)。

### 看请求卡在哪，或停止它

打开「实时」。每张卡片对应一条请求，能看到模型、站点、等待时间和已收到的数据量。

| 阶段 | 能确定的事 |
| --- | --- |
| 等上游回应 | 还没收到响应头；可能是连接、代理、排队或上游处理慢。 |
| 已回应，等内容 | 收到了响应头，但还没收到正文；不代表模型一定在思考。 |
| 正在返回 | 已收到内容；不代表回复已经完整结束。 |

卡片右上角的 **×** 只停止这一条请求，其他请求不受影响。刚结束的请求会再留一小会儿，方便看结果和重试经过。

「发呆超时」默认 **20 秒**：网关开始收到正文、推理或工具参数之后，如果这么久没有新的内容，就中断这条请求。
它不自动换站，也不记为分组故障；客户端可能自己重试，也可能直接报错。
等响应头和等第一个字的时间不计入——公益站首字等一两分钟是常事。可在「模型路由」或「实时」页调整，`0` 表示关闭。
手动停止或超时中断都**不保证上游不计费**。

### 临时停用，不删除配置

- **停用供应商或分组**：新请求不再选它，已有配置保留。模型名仍可能出现在客户端列表里，但没有可用候选就无法调用。
- **关闭侧栏的某种接口**：该接口的模型、分组及相关历史在界面里隐藏，请求也会被拒绝。重新打开即可恢复显示，不是删除。
- **从上游模型目录移除一个模型**：会连带移除指向它的候选，操作前会确认。只是暂时不用时，优先用停用开关。

### 某个站需要代理

编辑供应商，修改「出口」。不确定时先保持「跟随系统代理」。

- **直连**：不使用程序读取到的系统代理。
- **走指定代理**：只有这个供应商使用你填的代理。
- **走 VPS**：配置过这个预设才会出现，并不是网关自带了一台服务器。

「测一下」检查能不能通过这些出口联系到站点。**拿到 401 也可能说明网络已通，但不代表密钥或模型能用。**
如果代理软件开了 TUN（接管系统网络的模式），这里选「直连」仍可能被它接管，需检查代理软件自己的规则。详见[代理和证书](dev/maintenance.md#代理和证书)。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 拉取过模型，客户端还是看不到 | 是否只登记了上游模型目录，还没在「模型路由」新增模型；对应接口是否关闭。 |
| 报 404，提示模型未配置 | 客户端模型名是否一致、接口是否选对、候选是否启用。如果错误来自上游，还要检查它是否支持该路径和真实模型名。 |
| 报 401 / 403 | 看错误来源：可能是站点密钥失效、权限或访问限制；网关自己的本机访问限制也会返回 403。 |
| 报 429 | 看上游错误说明，常见原因是额度不足或请求过多，不要直接当成网关坏了。 |
| 报 502 / 连不上 | 检查站点地址、所选出口、代理和证书；文本日志在 `data/gateway.log`。 |
| 显示「流被截断」或完全没回复 | 只说明网关没有识别到完整结束，不能据此认定是谁的问题。曾有一次是压缩格式处理不匹配，详见[排查说明](dev/maintenance.md#抓包排查)。 |
| 普通聊天正常，但工具或搜索不工作 | 聊天成功不代表上游支持工具、搜索或客户端使用的全部格式。HTTP 200 也不能证明这些能力可用。 |
| token 数或费用对不上 | 带 `≈` 的是估算，不是账单。网关显示的用量来自上游报告或估算，最终费用仍要对照站点账单。 |

「转发记录」看的是已发生的请求，「实时」看的是正在发生的请求。排查时尽量保留**发生时间、客户端、模型、上游、状态码和报错原文**，比只说“又坏了”更容易定位。

### 搜索和长对话压缩能不能用？

网关可以转发搜索和压缩请求，但不能给上游增加它本来没有的能力：

- 独立搜索走 `/v1/alpha/search`。「搜索上游」可以为这类请求指定一个专用分组，不改变普通聊天使用的模型。
- 长对话压缩需要客户端和上游支持相应功能。支持 `/v1/responses` 不等于支持 `/v1/responses/compact`。
- 如果客户端没有发送这类请求，单改网关设置不会让它自动开始搜索或压缩。

以前的排查结论和配置实验都在[开发记录目录](dev/README.md)里，带日期的记录不代表现在的客户端版本或站点仍然如此。

## 数据和安全

- 网关只监听本机 `127.0.0.1`，没有登录和账户系统。**不要直接把它开放到公网或局域网。**
- 配置、密钥和转发记录主要保存在 `data/gateway.db`。**密钥是明文保存的**，不要公开这个数据库或它的备份。
- 抓包会保存请求和响应内容，可能包含对话、代码、个人信息或密钥。虽然会过滤常见鉴权头，**正文不会自动脱敏**，不要把整个抓包目录直接上传或提交。
- 「敏感词绕行」只是按你写的规则替换文本，**不是隐私保护功能**。规则过宽会改坏正常请求；没有明确需要时保持空表。
- 备份或升级前的数据保护方式见[数据与备份](dev/maintenance.md#数据与备份)。
