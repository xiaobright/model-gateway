# Model Gateway

多公益站上游聚合网关：把多个上游站点统一成一个入口，每个模型可单独指定当前使用的上游，切换时进行中的流不中断，新请求立即路由到新上游。

透传 OpenAI Responses、OpenAI Chat Completions 和 Anthropic Messages 三种格式，**不做格式转换** ——
下游打哪个路径，就原样转发到上游同名的路径：

| 下游路径 | 上游路径 | 谁在用 |
| --- | --- | --- |
| `/v1/responses` | `<站根>/v1/responses` | Codex（OpenAI Responses API） |
| `/v1/responses/compact` | `<站根>/v1/responses/compact` | Responses 独立 compaction |
| `/v1/alpha/search` | `<站根>/v1/alpha/search` | Codex custom provider standalone web search |
| `/v1/chat/completions` | `<站根>/v1/chat/completions` | OpenAI SDK / 各种 Chat Completions 客户端 |
| `/v1/messages` | `<站根>/v1/messages` | Claude Code（Anthropic Messages API） |
| `/v1/messages/count_tokens` | `<站根>/v1/messages/count_tokens` | Claude Code 用它算上下文占用 |
| `/v1/models` | — | 聚合清单，一份 JSON 同时满足各家形状 |

一条请求走哪种协议，由**它打进来的路径**决定，跟站点无关。站点那一侧的对应物是**分组**：
那把 key 走哪种接口。

协议只在 `gateway/protocols.py` 登记一次：写一个描述符（结束标记、usage 在哪、鉴权头、
错误体形状、客户端提示和默认统计/降级信息），再到 `proxy.py` 挂一条显式路由。名字集合、
指纹表、管理页下拉选项都从描述符派生；前端启动时读取只读的
`GET /admin/api/protocols`，不再另存一份协议 ID。这里仍是直通协议，不负责格式转换。

上游地址一律填**站根**，不带 `/v1`。Anthropic 客户端让你填的就是站根（它自己拼 `/v1/messages`），
OpenAI 那边习惯填到 `/v1` 为止 —— 同一个站两种说法，说明 `/v1` 属于接口路径而不属于站点。
所以库里统一存站根，`/v1` 由网关按接口补；粘进来带 `/v1` 的会被自动剥掉。

## 快速开始

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

启动（Windows 默认进入托盘模式，Linux/Mac 需加 `--no-tray`）：

```
.venv\Scripts\python main.py
```

或直接双击 `start-gateway.bat`。托盘图标右键菜单：打开管理页 / 开机自启开关 / 退出。

前台调试模式：

```
.venv\Scripts\python main.py --no-tray --open
```

## 供应商 / 分组 / 接口

三个概念，管理页和数据库都按这个分层：

- **供应商**（一个站）：一个站根地址，**一个供应商一个地址**，重复的地址会被拒掉。请求头覆写和
  启用开关也在这一层。它只回答「这个站在哪、怎么连」
- **分组**（一把 key + 一种接口）：同一个站常常给你两把 key，各自能拉到的模型还不一样；
  而 Claude 那把和 GPT 那把往往也是两把不同的 key。所以**接口挂在分组上**，
  分组各自维护自己的 `api_key`、`protocol` 和模型列表。切换、停用都到分组一级
- **接口**（`anthropic` / `openai` / `openai-chat`）：一条请求走哪种线格式。给某个 Anthropic 模型挑上游时，
  只列有 Anthropic 分组的供应商

模型属于哪个接口**不单独存**：它等于自己候选所在分组的接口。代价是同一个模型名的所有候选
必须在同一种接口上（跨接口挂候选返回 409），换来的是不会出现「标记说 A、实际连到 B」这种
自相矛盾的状态。跨接口调用会 404 并说清原因 —— 拿 Anthropic 的请求体去打人家的
`/v1/responses` 只会得到垃圾。

同一个分组下可以给一个模型名挂**好几条候选**，各指一个不同的上游真名（唯一约束是
「模型 + 分组 + 上游真名」，完全一样的还是拒）。一个站常常有好几个能用的模型 id，
而带日期后缀的那种（`claude-sonnet-4-5-20250929`）最容易被上游悄悄下掉 —— 挂两条
就等于给这把 key 备了个名字，上游回 404 时网关会自己去试下一条，见「自动降级」。
圆片上会把真名显示出来，不然同一个分组的两条长得一模一样。


一把 key 两种接口都能用的站不少。这时它是两个分组，在供应商的「编辑」里点「复制这把 key 到 …」
一键生成，名字可以一样（唯一约束是「供应商 + 接口 + 组名」）。

### 接口全局开关

侧栏底部每种接口一个开关。停用一种接口 = 在管理页里假装它不存在：它的下游模型、它的分组、
只有它的站都从列表和 `/v1/models` 里消失，打进来的请求在转发入口直接 404；统计、健康度、
转发记录里的历史行也一起藏起来。**描述符、分组、key、候选和历史记录都原样留着**，把开关
打开就全回来 —— 支持还在，只是暂时不看不打（Claude 侧的公益站集体躺平时就关掉 Anthropic，
省得每次刷新还给它算健康度）。状态存在设置表 `disabled_protocols` 里，重启不丢。

老库启动时自动升级，分三级：`api_key` 挂在上游行上的最老结构 → 每个上游变成一个供应商 +
一个「默认」分组；接口标记挂在 `upstreams.protocols` 上的上一版 → 标记搬到分组上、
`base_url` 收成站根、`model_meta` 整张表删掉；候选还是 `(模型名, 分组)` 复合主键的那一版 →
换成自增 `id`，唯一约束顺延到「模型 + 分组 + 上游真名」，这样一个分组下才塞得下第二条映射；
最新一版（v5）再加一张 `group_models` 上游模型目录表，把现有候选的 `(分组, 上游真名)` 回填进去。
历史配置一律标成 `openai` 接口
（今天之前网关只有 `/v1/responses`，这是事实不是猜测），`request_log` 里没有协议列的老记录
同样回填成 `openai`。库结构带版本号（存在 sqlite 的 `user_version` 里，见 `db.SCHEMA_VERSION`）：已经是当前版本
的库启动时直接放行 —— 不按形状猜、也不逐表查列；只有落后的库才走上面那条路，升完把号打上。
**迁移前会先备份成 `data/gateway.db.bak-<时间戳>`**，用的是 sqlite 自己的
backup API 而不是复制文件（WAL 模式下未落盘的内容还在 `-wal` 里，直接 cp 会拿到一个缺尾巴的库）；
备份只留最近 3 份 —— 迁移是一次性的，而 `.bak` 从来没人清理过，攒下去就是一堆没人看也没人敢删的东西。

同一个站不小心建成了两个供应商（两把 key 各建一个）时，进供应商的「编辑」改分组、把「所属供应商」
改成另一个，分组连着候选一起搬过去，然后删掉空掉的那个供应商即可。

## 使用流程

1. 浏览器打开 `http://127.0.0.1:8317/`（托盘模式下自动打开）
2. 「上游站点」点「添加供应商」：只填名称和站根地址（如 `https://xxx.com`，**不要带 `/v1`**，
   弹窗里会实时显示补出来的两个转发地址）。指纹覆写收在「请求头覆写」那个小按钮里，被拦了才用；
   「出口」默认跟随系统代理，只有被 IP 屏蔽的站才要动它（见「出口」那一节，旁边有「测一下」）
3. 保存后自动接上分组弹窗：**选接口**（Anthropic = `/v1/messages`，Claude Code 用；
   OpenAI = `/v1/responses`，Codex 用）→ 填这把 key → 保存 → 「拉取模型列表」→ **勾上就是登记
   上游模型，取消就是不再登记，即时生效**（组名 / 接口 / key 才需要点保存）。这一步只记下
   这个站能调到哪些模型，要不要对下游暴露在第 5 步的「模型路由」里做。上游列表里没有的可以手动填
4. 同一个站的另一把 key、或者另一种接口：在供应商的「编辑」里点「＋ 添加分组」；如果就是同一把
   key，点「复制这把 key 到 …」。列表里点一行的空白处也能展开看它的分组
5. 同一个模型名有了多条候选（可以在不同分组，也可以在同一个分组下指不同的上游真名）之后，
   在「模型路由」点圆片即完成切换（高亮的是当前生效的那条，也是自动降级的起点）。Claude 侧
   默认开着自动降级：打不通就按圆片从左到右的顺序换下一个，详见「自动降级」
6. 接 Claude Code：把它那四个档位当成四个模型名录进来（「新增模型」→ 接口选 Anthropic →
   选供应商和分组 →「上游那边的真实模型名」可以直接从那个分组拉到的模型里下拉选）。侧栏底部的
   **下游接入**里有两种客户端各自要填的地址和环境变量，可一键复制

管理页的分工：**模型路由**管「哪个模型在哪个接口下、走哪个分组」（分接口查看 / 切换 / 加候选 /
改候选 / 删候选 / 删模型），**实时**看现在正在跑什么（见下），**上游站点**管「站点怎么连」
（地址、请求头覆写，以及每个分组的接口、key 和模型列表），**转发记录**只读。

对下游暴露的模型清单 = 「模型路由」里录入的所有模型名（上游模型目录只决定能选哪些上游真名，
和是否暴露无关），与上游启用状态无关。带 `anthropic-version` 头请求
`/v1/models` 只会拿到 Anthropic 接口下的那些（Claude Code 就带这个头），认不出客户端时给全部。

## 实时请求

侧栏第二项。转发记录是「已经发生过的事」，这页是「现在正在发生的事」——
一条请求一张卡，1 秒一刷（接口纯内存、不碰数据库，秒数由前端本地走字）：

```
● claude-sonnet-5 → 公益站甲 · claude-sonnet-4-5-20250929            12.4s
  Claude Code · Anthropic · 流式 · 上行 2.3MB · 上下文 397.0K tok
  正在返回  已收 12.3KB ≈ 226 tok
  ↳ 第 1 次  站J · claude-sonnet-4-5   503                        0.9s
```

阶段分三个。**前两个必须分开看**：同样是「12 秒没动静」，还没拿到状态码是站连不上、或者
上游收了请求但不回话（也可能是系统代理的问题，见「和系统代理的关系」）；已经拿到状态码了
就是模型在想。处置完全不同。

| 阶段 | 含义 |
| --- | --- |
| 等上游回应 | 请求已经发出去了，还没拿到状态码。connect 超时 8 秒 —— 注意这一档不只是 TCP 握手，httpx 的 `send()` 要等到响应头才返回，所以「收了请求却不回话」也落在这里 |
| 已回应，等内容 | 状态码拿到了，响应体还没开始 |
| 正在返回 | 第一块字节已经转给下游，配上「已收 N」能看出是不是在挤牙膏 |

最后那行是**降级轨迹**：这条请求前面被哪几个候选拒过。同样的信息在转发记录里是分开的
两行（一行标「已降级」、一行标「第 2 次」），得靠相邻和时间戳自己拼；这里是一条线上的。

每条进行中的请求右上角有一个 **×**，点击即可中断。等响应头、等首字节、正在输出时都能用；
网关会关闭这条请求的上游连接，记录为「手动中断」，不再自动换站重试。其它请求照常运行。

结束的请求会**再留 90 秒**（最多 24 条，压暗一档、单独排在「刚刚结束」那一节里）。不留的话
空闲时整页是空的（Claude Code 两轮请求之间隔几十秒），而降级轨迹恰恰只在请求活着的那几秒
存在 —— 最想看的东西最看不到。

`count_tokens` 也列出来（打一个 `count_tokens` 标）：它虽然不进转发记录，但它**会走降级、
会踩断路器**，而且 Claude Code 打得挺勤，「这个站为什么在被打」的答案有时就是它。
不过它不计入「进行中」那个数字 —— 又多又快，混进去就没法当忙闲指示看了。

页面下半是**分组健康板**：哪些分组在冷却（带倒计时）、连续失败了几次、最近一次什么状态码。
断路器状态只在内存里，重启清零。

「进行中」那个数（侧栏胶囊、概览的 KPI、导航角标）现在也从这张登记表来，所以它包括还卡在
连接和等首字节的请求 —— 一个连不上的站要磨 8 秒，那 8 秒当然算进行中。

一个实现细节：登记是在 `relay()` 的 `finally` 里注销的，而「响应刚返回、生成器还没被迭代过
就被取消」那一瞬够不到 `finally`（没启动过的生成器 `close()` 不执行函数体）。所以读接口时
顺手扫掉超过 12 分钟的活跃条目并记一行日志 —— 真漏了看得见，而不是在页面上挂个幽灵。

### 包大小旁边那个 token 数

光看「上行 2.3MB」不知道这是多大一个请求，所以两个方向都折成 token 显示。规则是
**有真数就用真数，没有才估**，而且两个方向估的**不是同一件事**：

- **上行的 `≈` 可以当计费量看**。请求体每个字符都算进输入，字节数和 token 数一一对应
- **下行的 `≈` 是「收到手的内容」有多少 token，不等于计费量**。思维链发下来的是**总结过的**，
  而计费按**完整的**算，思维链越多两者差得越远；正文那部分是完整的没总结的。所以计费的输出量
  只认流末尾上游自己报的那个数，不拿字节去猜 —— 卡片上那个加粗的「计费输出」就是它。
  含思维链的流会打一个「思维链」标，说明这两个数为什么对不上
- 加粗的数都是**上游自己报的**。Anthropic 把 `input_tokens` 放在流开头的 `message_start` 里，
  所以「上下文多大」往往在第一块字节里就到手了（网关在头 8KB 里反复抽一次，数字被 TCP
  切成两半也能读全）；输出 token 在末尾的 `message_delta` 里。OpenAI 两个都只在末尾报
- 标尺不是拍的：转发记录每一行都现成放着字节数和上游报的 token 数，`stats.token_ratio()`
  从两千条里取中位数，每分钟重算一次。下行只认**没有思维链**的记录（那种记录里收到的和
  计费的对得上），而且只数**内容**字节 —— SSE 帧和 JSON 结构占了大头，拿整条响应的字节数
  去折 token 差十倍
- 某个方向的样本忽大忽小（p90/p10 超过 6 倍）时干脆不显示估值：那说明字节数里有个跟 token
  数无关的大常数项，给一个差十倍的数比不给更糟
- `count_tokens` 那张卡上的「上下文」是**精确值**：它的响应体就是这个数，而 Claude Code
  发它的目的正是问「我现在占了多少上下文」

一个副作用值得留着：估值和上游报的数摆在一起，谁报得离谱就看得见。真库里同一个下游模型，
上游真名是 `claude-opus-5` 的那批请求折出来是 2.8 字节一个 token，其余的是 8.3 —— 纯文本
2.8 字节一个 token 是不可能的（英文平均四个字符才一个），所以那几个站要么用了别的
tokenizer，要么在多报。

## 下游接入

| 配置项 | 值 |
| --- | --- |
| API 地址 | `http://127.0.0.1:8317/v1`（管理页右上角可一键复制） |
| API Key | 任意值（本地服务未做鉴权） |

```
curl http://127.0.0.1:8317/v1/responses \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-test", "input": "你好"}'
```

Responses 的 server-side compaction 继续走 `/v1/responses`，请求体里的
`context_management`、`tools` 和其它 Responses 字段由网关透传。需要显式压缩时可调用
`/v1/responses/compact`；返回的 compaction item 是上游生成的 opaque 状态，客户端应原样带到
下一次 Responses 请求，网关不会解析或裁剪它。上游必须真实支持对应能力，网关不会把普通模型变成
支持 compaction 或 hosted web search 的模型。

Codex custom provider 的 standalone web search 使用 `/v1/alpha/search`，网关透传路径、模型名和鉴权，
请求体中的 `commands`、`settings` 以及上游返回的 `encrypted_output`、`results` 均保持透明。若当前模型链的
首个上游对该独立 endpoint 明确返回 `404`、`405` 或 `501`，网关会仅为这条搜索请求尝试下一候选（不影响
普通 `/v1/responses` 的降级开关，也不会把 Tavily 等不同协议的结果伪装成 Codex 搜索结果）。上游仍必须真实
支持该 endpoint；`supports_standalone_web_search` 是上游侧的能力声明，不是本地网关开关。

如果希望所有模型的 standalone search 统一借用一个具备搜索能力的 上游，在「模型路由」卡片
右上角点「搜索上游」，选一个 OpenAI 分组，可再填一个该上游实际支持的上游模型名。设置后，所有
`/v1/alpha/search` 请求先走该分组，请求中的模型名保持不变（或换成你填的那个），由 上游 自己执行
Codex 凭据和模型别名选择；如果该分组返回 404/405/501，才尝试原模型的其他候选。普通
`/v1/responses` 和 `/v1/responses/compact` 不受影响。已设置时卡片上会挂一个当前目标的标签；
选「跟随模型的候选链（默认）」即可恢复。

对应的管理接口是 `PUT /admin/api/standalone-search-target`
（`{"group_id": 7, "model": "gpt-5.6-luna"}`，`group_id` 传 `null` 清除），当前值由
`GET /admin/api/standalone-search-target` 返回。上例中的 `7` 是当前数据里 `站B / 默认`
分组的 ID，实际部署应以 `GET /admin/api/upstreams` 返回的分组 ID 为准。`model` 可留空 =
用请求里的模型名；当前 站B 用 `gpt-5.6-luna` 或 `gpt-5.6-terra`，这个改名只作用于
`/v1/alpha/search` 的上游请求，不会改变当前 Codex 对话模型。

上游返回的非 200 状态码与错误体会原样透传（比如额度用尽的 429）。网关自己产生的错误
（404 没配这个模型、502 连不上上游）按下游打的那个路径给对应形状：`/v1/responses` 给
OpenAI 的 `{"error": {...}}`，`/v1/messages` 给 Anthropic 的 `{"type": "error", "error": {...}}`。

## 接 Claude Code

Claude Code 按 haiku / sonnet / opus / fable 四个档位选模型。把这四个档位当成四个模型名录进来
（接口选 Anthropic），每个档位指向某个上游的真实模型 id，就能在网关里随时改档位落到哪个站、
哪个模型，不用重启客户端：

| 模型名（对下游暴露） | 上游 | 上游那边的真实模型名 |
| --- | --- | --- |
| `claude-opus-5` | 公益站甲 | `claude-opus-4-1` |
| `claude-sonnet-5` | 公益站甲 | `claude-sonnet-4-5` |
| `claude-haiku-4-5` | 公益站乙 | `claude-haiku-4-5` |

客户端侧（侧栏「下游接入」里可以直接复制，模型名会按你实际录入的填）：

```
setx ANTHROPIC_BASE_URL http://127.0.0.1:8317
setx ANTHROPIC_AUTH_TOKEN whatever
setx ANTHROPIC_DEFAULT_OPUS_MODEL claude-opus-5
setx ANTHROPIC_DEFAULT_SONNET_MODEL claude-sonnet-5
setx ANTHROPIC_DEFAULT_HAIKU_MODEL claude-haiku-4-5
```

注意 `ANTHROPIC_BASE_URL` 填到端口为止，Claude Code 自己会拼 `/v1/messages`。

几个坑：

- **鉴权头**：Anthropic 官方认 `x-api-key`，中转站大多两种都认，所以分组存了 key 时网关会
  同时写 `x-api-key` 和 `Authorization: Bearer`。`x-api-key` 必须**覆盖**——Claude Code
  自己会带一个占位 key，只设 Authorization 的话那个占位值会把真 key 压掉。某个站只吃一种头时，
  用该上游的「请求头覆写」把另一个写成 `null` 删掉。拉模型列表（`<站根>/v1/models`）也按分组的
  接口发头：Anthropic 分组会带上 `x-api-key` 和 `anthropic-version`，UA 也不再自称 codex
- **haiku 档很费**：Claude Code 用 haiku 档跑很多琐碎后台活（会话标题、各种小判断），量不小。
  全指到只有 opus 的站，等于用 opus 的价格干这些活；有便宜档的话让 haiku 单独指过去。
- **1M 上下文**：Claude Code 把它编码成模型名的方括号后缀（`claude-opus-5[1m]`），正常情况下
  它自己会摘掉后缀、换成 `anthropic-beta: context-1m-2025-08-07` 头。但这条路径有已知的漏网
  （auto 模式的分类器会把带后缀的名字原样发出去，anthropics/claude-code#81142）。所以网关自己
  兜了一层：**后缀只用来推断意图，绝不往上游传**——摘掉后缀再查路由，客户端没带那个 beta 头时
  补上，已经带了别的 beta 就追加而不是覆盖。配置里的「真实模型名」写成带后缀的形式也一样处理。
- **档位关键字兜底**：上面那几个环境变量漏设一个、或者以后模型改名，客户端就会发来一个没配过的
  具体 id。这时网关会按名字里的档位关键字（haiku / sonnet / opus / fable）在**同一个接口下**
  找同档位的那条配置，唯一命中就落过去并记一行日志；同档位有多个名字、或者认不出档位，
  仍然返回 404，不瞎猜。
- **想让某一档固定按 1M 请求**：新增或改候选时勾上「按 1M 上下文请求」，等于把真实模型名存成
  `名字[1m]`，之后这一档每个请求都会带上 beta 头，圆片上会显示一个 `1M` 标。上游不支持时会返回
  4xx，别盲开。已有候选想改，把鼠标移到圆片上点 ✎。

## 设计要点

- 路由决策发生在请求进入时，切换只改 SQLite 里的一行记录，已建立的 SSE 连接不受影响，因此无需重启进程即可热切换
- **地址拼接**：库里存站根，`upstream.endpoint()` 按接口补 `/v1` 再接具体路径。存的时候也会剥掉
  尾部的 `/v1`，所以粘错了不会拼出两个
- **模型名改写**：请求体里唯一会被动的字段是 `model`，换成该候选配的「上游那边的真实模型名」。
  两边名字一致时继续发原始字节，所以没配改名的请求仍然是字节级透传。重新序列化用
  `ensure_ascii=False`，否则中文请求体会涨三到六倍
- **完全透明中转**：客户端请求头原样转发（仅重写 host/content-length 等必须由代理处理的），命中的分组存了 key 才覆盖鉴权头，key 留空则连鉴权头都透传
- **请求头覆写**：每个供应商可配 JSON 覆写（编辑弹窗），用于通过有客户端指纹检测的站点；值 null 表示删除该头。它在最后应用，能改掉网关自动加的任何头。它在供应商一级 —— 一个站同时挂两种接口又要两套指纹的情况还没遇到，遇到了再往分组上加一层
- **出口**也在供应商一级，理由同上，而且它和 Base URL 回答的是同一个问题（这个站在哪、怎么连）。
  一个出口一个 httpx client（代理是建 client 时定的，没法按请求换），而每个候选可能属于不同的
  供应商，所以取 client 那行在候选循环里面
- 供应商停用、分组停用都只影响新请求的路由，不改变对下游暴露的模型清单；删除当前活跃候选会自动把流量切到剩余候选之一
- 路由解析是三表 join（候选 → 分组 → 供应商），条件里带上**请求的协议**（`g.protocol=?`），
  `api_key` 取自命中的**分组**再填进转发用的上游描述里，所以 `proxy.py` 完全不需要知道分组的存在
- 转发用一个全局复用的 httpx client，省掉每个请求一次 TLS 握手
- **自动降级的落点就在 `proxy.forward` 里 `client.send()` 刚返回那几行**：状态码已经拿到手、
  还没往下游发过任何字节，换个上游重试客户端完全无感。第一个字节一旦发出去就不能再换了 ——
  下游会看到两段拼接的回复，而上游那边的 token 已经计费了。所以流开始之后断掉的（`upstream_abort` /
  `truncated`）不重试，这是这套机制的边界
- 数据存于 `data/gateway.db`，端口可通过 `data/settings.json` 的 `{"port": 8317}` 覆盖
- 模型名允许带 `/`（如 `deepseek-ai/DeepSeek-V3`），所以删除走 query 参数而不是 URL 路径

## 自动降级

一个请求打不通就按候选顺序换下一个，连着坏的站进冷却。开关**按接口分开**（模型路由卡片头上）：

| 接口 | 默认 | 为什么 |
| --- | --- | --- |
| Anthropic | **开** | 那边全是坏得勤的中转站，能通比用哪个站重要 |
| OpenAI | **关** | 除了一个公益站都是花钱买稳定的，换站要人点头 |

规则：

- **顺序**是配置：候选圆片从左到右就是依次尝试的顺序，在圆片的 ✎ 里前移 / 后移，改完即时生效。
  最稳的那个站排最后当保底
- **起点**是当前生效的那个候选（高亮的圆片）。手动点圆片切换永远即时生效，而且会**清掉它的冷却** ——
  你明确指定了，就立刻给它机会
- **一次请求最多实打 3 个候选**（被跳过的不算），每次耗时都算在这一个请求头上。已经耗了
  180 秒、或者客户端已经断开，就不再开新尝试
- 失败分两类，处置不一样：

  | 类型 | 状态码 | 处置 |
  | --- | --- | --- |
  | **站级** | `408 / 425 / 429 / 5xx / Cloudflare 52x`、`401 / 403`（key 死了，换个分组就是换一把 key）、`413`（体积上限每个站不一样）、连不上 | 记一次失败、够数就进冷却，而且**这个分组本次剩下的候选全部跳过** —— 同一个站绝不在一次请求里立刻重试（客户端自己已经在重试了，再叠一层只是让每次失败变长） |
  | **模型级** | `404` | 这个站没有这个模型 id。**不算这个分组的锅**：站是通的、key 是好的，所以不记失败、不进冷却，直接试下一条候选 —— 可以是同一个分组里的另一个真名 |

  `400 / 422` 仍然不重试：请求本身有问题，换谁都是同样的答案
- **冷却**：同一个分组连续失败 2 次就冷却 90 秒，再失败翻倍，封顶 10 分钟。冷却期内自动降级
  跳过它（所有候选都在冷却时照旧按顺序打，不会因为「大家都冷着」直接给客户端一个 503）。
  期满会放它试一次，再失败就进更长的冷却
- 带 `store` / `previous_response_id` 的 OpenAI 请求**不降级**：上游可能已经把它存下来了才失败
- **每一次尝试都留一行转发记录**。被降级接住的那次失败标成「已降级」，胜出那次标「第 N 次」——
  降级最怕的是把问题藏起来，而那次失败是真花了钱的。累计卡片上的「救回 N」就是
  `attempt > 1 且成功` 的条数

策略参数（重试几次、冷却多久、哪些状态码算可重试、connect 超时）集中在 `gateway/failover.py`
顶部十几行，改一行就换一套策略；断路器状态只在内存里，重启即清零。

这套设计是拿真库里 2000 条记录定的：同一个上游最长连续失败 60 次（站A）、28 次（站B）、
10~11 次（站J / 站K）—— 故障是「坏一阵子」而不是「坏一下」，所以「成功一次就黏住」用**冷却**
实现而不是去改生效指针：冷却天然覆盖这一段，期满自动回到第一个候选（OpenAI 侧 站A 累计命中过
1.5 亿缓存 token，那边必须能自己回去），也不会悄悄改写你手动选的东西。另外 104 个 502 全是连不上、
平均白等 16.6 秒，所以 connect 超时从 15 秒收到 8 秒。

## 只对本机开放

- 仅监听 `127.0.0.1`，不对局域网开放
- 另外会校验 `Host` 头必须是回环地址，挡掉 DNS rebinding（攻击者把自己的域名解析到 127.0.0.1）
- `/admin/api/*` 拒绝带跨站 `Origin` / `Sec-Fetch-Site: cross-site` 的请求：管理接口没有鉴权，
  否则任何网页都能悄悄改你的上游配置或调 `/admin/api/shutdown` 关掉进程
- 如果你把网关配到了别的主机名下（改 hosts 之类），会收到 403，属预期行为

## 转发记录与统计

管理页底部「转发记录」：最近 50 条请求的客户端（按 UA 识别）、**协议**、模型、上游、状态码、token 用量
（输入/输出/缓存命中）、耗时、备注，以及顶部的累计统计与缓存命中率。右上角的分段选择器可以只看
Anthropic 或只看 OpenAI 的记录（纯前端筛选，只把行藏起来，不重新拉数据也不打断增量渲染）。
模型那一列在配了改名时显示 `档位名 → 上游真名`，上游那一列在分组名不是「默认」时显示 `供应商 · 分组`，
否则从记录里看不出实际跑的是哪个模型、用的哪把 key。
数据持久化在 `request_log` 表，只保留最近 2000 条。`count_tokens` 不计入记录也不计入活跃流，
否则它会把累计次数和模型热度冲得没法看。备注列会标出异常结束的请求：

| 备注 | 含义 |
| --- | --- |
| 流被截断 | 上游 200 但整条流都没出现完成事件，通常是劣质上游 |
| 上游断流 | 传输中上游连接断了 |
| 客户端断开 | 下游客户端在收到完成事件**之前**就挂断了（真的中断） |
| 连不上 | 连上游都没连上 |
| 已降级 | 这次失败被自动降级接住了，客户端没看见它 —— 但这次调用是真花了钱的 |

上游那一列后面的「第 N 次」表示这条是同一个请求的第 N 次尝试（前 N-1 个候选没打通）。

完成事件按协议不同：Responses API 是 `response.completed` / `[DONE]`，Anthropic Messages 是
`message_stop`。检测走滑动窗口，标记被 TCP 切成两半也能认出来。
很多上游发完完成事件后并不主动收连接，而 codex 拿到完成事件就走了，这种情况算正常收尾（记 `ok`），
不标「客户端断开」。

token 用量也是按协议分开抓的。Anthropic 把 usage 拆在流的两头：`input_tokens` 和
`cache_read_input_tokens` 只出现在**开头**的 `message_start` 里，终值 `output_tokens` 在**末尾**的
`message_delta` 里。SSE 每个 delta 事件一百多字节只带几个字，几百 token 的回复就能把 `message_start`
挤出尾部窗口，所以头尾各留一段（8KB / 64KB）。

「上游站点」表的**实测格式**列回答的是「这个站声明的接口到底能不能用」。分组只是声明「这把 key
走哪种格式」，能不能通没法静态探测，只能看实际跑过的请求：每种格式显示跑过多少次，按该格式
自己的成功率上色。一个只有 claude 的站被 Codex 打过、或者反过来，在这一列一眼就能看出来是红的。

文本日志在 `data/gateway.log`，写满 5MB 就滚成 `.1`（原来的 `.1` 变 `.2`），一共留三份（含当前的）。
调试时可放一个 `data/capture.flag`，
下一个请求的请求头会被 dump 到 `data/captured_headers.json`（Authorization、Cookie、x-api-key 等敏感头
写成 `<redacted>`），dump 完 flag 自己删掉。

## 出口：每个站从哪扇门出去

同一台机器上「有的站必须走代理、有的站必须**别**走代理」是常态：公益站按 IP 屏蔽，
而校园网 IP 和机房 IP 各自被不同的站拉黑 —— 拿 Claude 那几个站来说，校园网 IP 全被挡，
得走 VPS；可 站A 反过来把机房 IP 挡了，只能直连。所以出口是**每个供应商**一个设置，
和 Base URL 同一层（在供应商弹窗里，紧跟着地址）：

| 出口 | 含义 |
| --- | --- |
| 跟随系统代理（默认） | httpx 自己去读环境变量和 Windows 注册表里的系统代理（Clash 那种）。今天的行为，升级之后一个站都不变 |
| 直连 | 连系统代理一起关掉（`trust_env=False`）。httpx 不只看环境变量、在 Windows 上还读注册表，所以只把 proxy 设成 None 是不够的 |
| 走 VPS | 预设门：你自己在 VPS 上部署的代理，下拉里选中就行，不用手打 URL。部署了（设置表里有 `egress_vps`）才出现，见下文 |
| 走指定代理 | 只有这个站走它。`http://` 或 `socks5://`（socks5 要额外装 `socksio`） |

**自签证书的 https 代理**用 `#ca=` 把签发的证书钉进信任列表，比如
`https://user:pass@host:8443#ca=data/vps-proxy-ca.pem`。自签的那张证书系统根证书验不过，
钉上就能过，而且系统根证书原样保留、不影响别的站。相对路径按仓库根解析，保存时就地检查
文件在不在；只对 https 代理有意义 —— socks5/http 的门没有要验的证书。

**「走 VPS」这扇门的部署**（一次性的运维事实，都记在 VPS 上）：一个 gost（v3.3.0，
`systemd: gost-proxy.service`）监听 `:8443`，带账号密码、TLS 用 `/etc/gost/` 里十年期的
自签证书（SAN 含 VPS 的 IP）。改端口 / 换密码：改 unit 里 `-L` 那行，`daemon-reload +
restart`，再把新 URL（带 `#ca=` 尾巴）写进设置表 `egress_vps`、新证书拷到 `data/vps-proxy-ca.pem`；
已保存的站要各自把出口重选一遍（存的还是完整 URL，预设变了不会自己跟）。

**不需要 mihomo 之类的代理内核**：内核的存在意义是替「不知道有代理」的进程做拦截（TUN、
系统代理），而网关自己就是发请求的那个客户端，socket 是它自己开的，按站选出口只是建 client
时多一个参数。省掉的不只是一个内核，还有两个内核抢系统代理和 TUN 路由的那场架。
代价是网关只会「拨号」不会造隧道，所以 vless / shadowsocks 这类得先由本机的内核落成一个
http/socks 端口（mihomo 的混合端口 `7890` 就是），填进来会被直接拒掉而不是等转发时才炸。

「测一下」按钮把这个站从每扇门各打一次 `<站根>/v1/models`，报回「通不通 / 状态码 / 多少毫秒」。
拿到任何状态码都算这扇门能到站（401 也算 —— 问的是网络，不是 key）。它是「实测格式」那一列
在网络层的兄弟：哪个 IP 被哪个站拉黑只能实测，猜不出来。三扇门并发打，一扇被挡住的门要磨满
connect 超时，串行就得等三倍。

几个坑：

- **回环地址**（`127.0.0.1` / `localhost` / `[::1]`）在「跟随系统」和「直连」下强制不走代理，
  否则连本机上游都要绕一圈。但**明确给某个站指了代理时不再豁免** —— 你都指名了，就按你说的走
- **TUN 模式**下这个设置救不了你：TUN 是在路由层截包的，进程内怎么写都逃不出去。
  真被 TUN 接管了，得去 Clash 那边给目标 IP 加一条 `IP-CIDR,<ip>/32,DIRECT`。
  **VPS 自己的 IP 已经加了**：Clash 的全局覆写 `vps-direct`（挂在 配置文件 上），
  内容就一行 `IP-CIDR,203.0.113.10/32,DIRECT,no-resolve`。没它的话 TUN 会把去 VPS 的
  连接（gost 门、SSH）抓进「节点选择」——经 VLESS 隧道绕回同一台 VPS 再出来，握手就出错。
  换 VPS 的 IP 时记得同步改那份覆写。注意这只豁免了 VPS：其他「直连」站在 TUN 下
  仍会被 Clash 按规则路由（非 CN 照样进代理）
- 「连不上」类记录里的 `getaddrinfo failed` / `ConnectTimeout` 有可能是代理侧的问题，
  不一定是上游挂了；排查时先看「实时」页卡在哪个阶段，再看 `data/gateway.log` 里的异常类型
- 拉模型列表也按出口走。不然「转发是好的、拉列表却失败」，最容易被当成 key 填错了

## 开机自启

托盘菜单勾选「开机自启」即在 Startup 目录创建指向 `pythonw.exe main.py --tray` 的快捷方式，再次点击取消。

## 运行与退出

- 单实例：重复启动会弹窗提示，不会开出第二个托盘图标
- 正常退出用托盘菜单的「退出」，或 `curl -X POST http://127.0.0.1:8317/admin/api/shutdown`
- 注意：venv 的 pythonw 启动器在任务管理器里表现为一对父子进程（同秒创建），这是正常现象；若必须用任务管理器强杀，请右键「结束任务树」而不是只结束单个 PID
- 启动失败（如端口被占用）会以弹窗提示，不会无声消失

Anthropic 侧另外验证：模型名改写到上游真名、`x-api-key` 覆盖掉客户端的占位 key、`anthropic-version`
补默认值、`[1m]` 后缀被摘掉且 beta 头被注入（客户端已有别的 beta 时追加）、档位关键字兜底命中与不瞎猜、

没配改名时请求体字节级不变、`count_tokens` 转发但不进记录、`/v1/models` 同时满足两种形状、
转发记录里落下协议且上游健康按协议拆分（含「某个格式全失败」这种情况）、静态资源带 `no-store`。

分组各走一种接口）、**模型绑定在一种接口上**（跨接口调 404、跨接口挂候选 409、乱填接口 400）、
**拉模型列表按分组的接口发鉴权头**（Anthropic 分组要带 `x-api-key` + `anthropic-version`）、
`/v1/models` 按 `anthropic-version` 头过滤、改候选的上游真名与 1M 开关（`PUT /admin/api/models`）、
有候选的分组不许改接口、一键把 key 复制到另一个接口、删掉最后一个分组之后站点变成不可用而不是报错、
两级迁移（最老的 `api_key` 挂在上游行上 → 分组；上一版 `upstreams.protocols` → 分组的接口 +
站根 + 删 `model_meta` + 回填老记录的协议列，含幂等重跑与「两种格式都标了」的站）、
同一个供应商的两个分组各用自己的 key 拉到不同的模型列表、两个分组之间热切换、
把分组搬到另一个供应商下完成合并、供应商停用与分组停用都能挡掉路由、重复 Base URL 被拒并提示去加分组、
批量导入撞上「已经在另一种接口下暴露」的名字时只跳过它并报出是哪些（拉一次几十个，不能整批退回）、
拉取失败的报错里带上实际请求的 URL。

自动降级另外验证（mock 站可以在运行中「生病」，回指定状态码）：第一个候选 503 时换下一个且
**请求体里的 model 和 x-api-key 都换成新候选那份**、流式一样能降级且不会混进坏站的半截响应、
**OpenAI 侧默认不降级**（原样透传 503，打开开关才换站）、`400` 不重试、全坏时只打 3 个就把最后
那个的响应还给客户端、连续失败 2 次进冷却之后请求根本不再打它、手动切换清掉冷却、
`models/order` 决定第二个轮到谁、带 `store` 的请求不降级、`attempt` 落库且「救回」计数正确。

同一分组多条映射另外验证：一个分组能挂同一模型的两个真名（连真名都一样才算重复，
改真名改成重复的返回 409）、能手动切到同分组的第二条、**上游回 404 时换同分组的下一个真名
且不让整把 key 进冷却**、**站级 503 时同分组的兄弟候选一起跳过**（同一个站一次请求只打一遍）、
分组级删除会把同分组的几条映射一起去掉并自动改道，以及第三级迁移（复合主键 → 自增 id，
候选一条不少，迁完就能在同分组加第二条）。

实时页另外验证：流进行中时 `/admin/api/inflight` 能看到这条请求（阶段、上游、分组、下游客户端、
上游真名都对得上），流走完之后从「在跑」转进「刚结束」且计数归零、被降级接住的那次失败留在
胜出请求的轨迹里、`count_tokens` 列出来但不计入「进行中」也不进转发记录、
没配过的模型（连上游都没碰）不登记，以及**流还在跑就能拿到上游报的上下文大小**
（Anthropic 的 `input_tokens` + `cache_read` 在流开头的 `message_start` 里，输出 token 要等末尾）。

估 token 的标尺另外验证：从转发记录里量出「多少字节摊一个 token」（上行按接口算上下文，
Anthropic 要把缓存读取加进去）、**某个方向忽大忽小时返回 0 = 不给估值**、
**带思维链的记录不进下行的标尺**（发来的是总结、计费按完整的算）且思维链字节和内容字节
都落库，以及这份标尺真的跟着 `/admin/api/inflight` 发给前端。

出口另外验证（测试里起一个真的 HTTP 代理，只有「字节真的从那扇门出去了」才算验过）：
填了代理的站连**拉模型列表**都从代理走、没填的站不走、`direct` 连 `trust_env` 一起关掉而
回环 mounts 只在没指定代理时挂、vless 这类地址直接 400 拒掉、以及「测一下」能报出
每扇门通不通（把代理换成没人听的端口，那扇门报不通、另外两扇照旧通）。自签证书那套
（`#ca=`）另有一对：钉了证书字节真的能从 TLS 门过、不钉就过不了握手，`#ca` 的语法 /
文件在不在保存时当场 400，「走 VPS」预设从设置表里来、没配就没有。


测试客户端一律 `trust_env=False`，否则系统代理会把回环请求也接走，`connect_failed` 之类的断言会拿到
代理返回的 502。

## 前端

`web/` 没有构建步骤，浏览器直接吃原生 ES 模块：`index.html`（结构）、`style.css`（设计令牌 + 组件，
跟随系统深浅色，右上角可手动切换）、`app.js`（视图路由 + 一张 `data-act` 动作表，事件走委托）、
`views.js`（各视图的渲染）、`charts.js`（SVG 图表）、`motion.js`（动效与全局光照）、`util.js`（纯工具）、
`group-editor.js`（分组编辑会话、模型列表请求和局部写入锁）、
`async-state.js`（同一数据域的刷新合并）。
协议筛选、分组接口选择和复制目标共用 `/admin/api/protocols` 的最后一份有效投影；加载失败时保留
旧列表并显示重试入口，首次失败不会拿空值提交配置。

### 上游模型目录与下游暴露

「上游站点」里每个分组维护一份**上游模型目录**：这个站能调到的上游真名。分组弹窗里的勾选
（拉取模型列表 / 手动填）只登记目录，不会自动对下游暴露；上游站点那一列显示的就是这些真名，
不是下游名字。要不要对外暴露由「模型路由」单独决定：一个下游模型名挂到某个分组、映射到某个
上游真名。两边分开之后，删掉一条下游候选不会把「这个站有这个模型」一起忘掉；反过来从目录里
去掉一个上游模型时，指向它的下游候选会一起下线（会先确认）。

模型路由仍支持 `/admin/api/models/transfer`：在同一个 SQLite 事务里把候选复制 / 移动 / 合并到
另一个下游模型，完整保留分组及上游真实模型（含 1M 后缀），已有目标的首选和顺序不变，迟到的
来源快照或不同协议会被拒绝，不做协议转换。

`dev/` 里是做视觉效果时的一次性实验页（玻璃质感那版），不参与运行、也不在 `/static` 下 ——
放在 `web/` 里会被当成静态资源服务出去。

轮询分三档：3 秒取「进行中」那两个数（侧栏和 KPI），15 秒取统计 / 记录 / 配置（断路器的冷却
剩余要在圆片上走字），实时页显示时另开 1 秒一次的 `/admin/api/inflight`。三档都在标签页
不可见或有弹窗打开时停掉。实时页的秒数不靠轮询：本地每 200ms 按「这条什么时候开始的」重算，
否则要么一秒跳一格，要么得把轮询压到 200ms 去。

`/static` 一律带 `cache-control: no-store`。ES 模块的 `import './views.js'` 是裸路径，没法挂
`?v=` 版本号，而只给入口挂版本号更糟：新的 `app.js` 配上缓存里的旧 `views.js`，页面会半坏不坏。
localhost 上这点带宽无所谓，代价换来「改完刷新就生效」。

弹窗 `showModal()` 后会进浏览器的 top layer，它的 `::backdrop` 带模糊，会盖住所有普通页面内容
（`z-index` 开多高都没用）。所以这两样东西也必须进 top layer 才不会被糊掉：

- **确认框**是页面内第二个 `<dialog>`，后 `showModal()` 的在上，于是它清晰、下层弹窗被模糊
- **提示条**用 `popover="manual"`，每次新提示都重新 `showPopover()` 一次，靠「后进的在上」压在弹窗之上
