## 这里还有什么

`dev/` 里的页面实验和诊断脚本不是网关启动所必需的文件。
尤其是 `find-sensitive-line.py`：它会访问上游、可能计费，并临时改变文本替换规则。运行前先看[使用限制](maintenance.md#请求文本替换)，不要为了“顺便检查”直接执行。

历史记录中的提交号、旧代码行号、临时文件位置保留用于追溯，不保证仍能在当前工作区直接打开。
如果临时证据文件已经不存在，只能说现有记录如此，不能声称又验证了一遍。

## 以后文档尽量这样写

1. **先写结论。** 做了什么、有什么影响、还要不要处理，先用几句话说清。
2. **用具体动作代替抽象词。** 例如“切换分组后，旧请求不能覆盖新表单”，不用“收敛异步状态边界”。
3. **必要术语解释一次。** 保留真正要复制的字段、错误原文和命令，不让读者靠猜缩写理解内容。
4. **把已完成、待决定、已停用分开。** 更新结论放开头，不藏在长文末尾。
5. **测试说范围和结果。** 写“这次跑了什么、哪些没跑”，不只写“全绿”“闭环”“已经兜底”。
6. **不拿猜测当事实。** 收到 200 不等于功能完整，估算 token 不等于账单，旧截图不等于现状。
7. **首页不要记流水账。** 使用方法放首页，维护细节放维护说明，历史经过放带日期的记录并从本页链接。
