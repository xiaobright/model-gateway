### 增加一种接口时

在 `protocols.py` 登记该接口的实际规则，在 `proxy.py` 明确增加入口，再补转发、统计和客户端接入测试。
页面通过 `GET /admin/api/protocols` 读取名称等展示信息，不应另存一份固定的接口名单。

这只是增加一种**原样转发的接口**，不是增加格式转换。工具、图片、流式结束等行为仍要按该接口实际验证，不能只加一行配置就宣布兼容。

## 接口与转发规则

### 支持的路径

| 方法与路径 | 用途 |
| --- | --- |
| `POST /v1/responses` | OpenAI Responses。 |
| `POST /v1/responses/compact` | 转发独立的对话压缩请求。 |
| `POST /v1/alpha/search` | 转发独立搜索请求。 |
| `POST /v1/chat/completions` | OpenAI Chat Completions。 |
| `POST /v1/messages` | Anthropic Messages。 |
| `POST /v1/messages/count_tokens` | 转发上下文 token 数量查询。 |
| `GET /v1/models` | 返回网关配置的客户端模型名，不是直接返回某个站点的目录。 |

转发入口也保留了去掉 `/v1` 的短路径别名。站点地址保存时会去掉末尾 `/v1`，转发时再补完整路径。
可以保存带有服务前缀的地址，例如 `https://api.example.com/anthropic`；这里的 `/anthropic` 不是要去掉的 `/v1`。

### 模型、分组和停用规则

- 数据库里的接口标识是 `openai`（Responses）、`openai-chat`（Chat Completions）、`anthropic`（Messages）。不要把 `openai` 当成前两种格式的总称。
- 一个供应商对应一个地址；同地址的多把 Key 放在不同分组，不重复建供应商。
- 一个分组保存一把 Key 和一种接口。同一供应商内，分组按「接口 + 组名」区分。
- 同一个客户端模型名可以在多种接口下各有独立候选链；首选、顺序、转发和用量统计都按「模型名 + 接口」区分。
- 同一模型可以在同一个分组里配置多个真实模型名；「模型 + 分组 + 真实模型名」完全相同才算重复。
- 有候选的分组不能直接改接口。复制 Key 到另一种接口时，不要把它理解为候选和模型也已自动配好。
- 上游模型目录只回答「这个分组有哪些模型」。候选被删除不会自动忘记目录；从目录移除模型则会连带删除指向它的候选，需要先确认。
- 供应商/分组停用不删除客户端模型名；接口全局停用还会隐藏该接口的模型和相关历史，但数据保留。
- 已配置但全部停用的链返回 404，不会落到另一个同档位模型；只有该接口下未配置的名字才尝试档位兼容。
- `/v1/models` 通过 `anthropic-version` 请求头识别 Anthropic 客户端，只返回该接口的模型；其他情况返回未被全局关闭的接口下的模型。

旧编排的候选复制/移动接口和旧批量暴露接口已移除，历史实现见[旧编排查阅指引](orchestration-history.md)。
当前新增候选用 `POST /admin/api/models`，上游目录登记用 `POST /admin/api/groups/{id}/models`，两种含义不要混用。
`DELETE /admin/api/models` 用 `route_id` 删除单条，或用 `model_name` 与 `protocol` 删除一条链。
旧 `group_id` 删除参数和其他未知参数会返回 400，避免把局部删除误当成整模型删除。

### “不转换格式”不等于所有字节都不改

目前会按需要处理这些内容：

1. 把请求的 `model` 换成候选配置的真实模型名；处理模型名上的 `[1m]` 后缀。
2. 如果配置了「敏感词绕行」，按规则替换请求里的字符串。
3. 处理转发所需的请求头，使用分组 Key、接口默认头和供应商的「请求头覆写」。
4. 按网关自身的解压能力填写 `accept-encoding`，并使响应的压缩标记与实际传出的内容一致。

**没有模型改名、没有文本规则命中时，请求体沿用原始字节。** 需要重建 JSON 时使用 UTF-8，不把中文改成大串 `\uXXXX`。
响应的内容观察器只做统计，不改写模型输出；HTTP 压缩形式和网络分块不保证与上游完全一样。

分组 Key 非空时覆盖鉴权头；Anthropic 同时设置 `x-api-key` 和 Bearer 头。Key 为空时保留客户端鉴权信息。
供应商的请求头覆写最后应用，值为 `null` 表示删除该头，也能覆盖前面自动生成的值。只在确认站点确实需要时使用。

上游最终返回的错误状态和内容会继续转发。网关自己产生的错误，按对应接口返回 OpenAI 或 Anthropic 的错误结构。

### 搜索与压缩

普通 Responses 请求中的 `tools`、`context_management` 等字段会继续转发。
压缩结果里的不透明状态由上游生成，网关不解密、不伪造，也不能从普通聊天成功推断压缩已经发生。

独立搜索可以通过管理页「搜索上游」指定一个 OpenAI Responses 分组和可选的真实模型名：

- 只影响 `/v1/alpha/search`，不改变普通聊天或压缩使用的候选。
- 未填真实模型名时，用搜索请求里的模型名。
- 目标返回 404/405/501 时，有其他可用候选便可继续尝试；这类“不支持搜索接口”不记分组故障。
- 搜索可以在普通 OpenAI 自动降级关闭时尝试其他候选，仍受请求状态字段等限制；其他失败由共用转发流程处理。
- 它不会把其他搜索服务的结果转换成 Alpha Search 格式。

相关管理接口为 `GET/PUT /admin/api/standalone-search-target`。写入字段为 `group_id`、`model`；`group_id: null` 清除设置。
分组 ID 必须从本机的配置中取得，不要照抄历史报告里的数字。

客户端是否发独立搜索，取决于客户端自己的配置和版本。`supports_standalone_web_search` 不是本项目的网关开关。

## Claude Code 配置

通常直接从管理页「下游接入」复制。需要手填时，下面是 PowerShell 当前窗口的示例：

```powershell
$env:ANTHROPIC_BASE_URL = 'http://127.0.0.1:8317'
$env:ANTHROPIC_AUTH_TOKEN = 'local-only'
$env:ANTHROPIC_DEFAULT_OPUS_MODEL = 'my-opus'
$env:ANTHROPIC_DEFAULT_SONNET_MODEL = 'my-sonnet'
$env:ANTHROPIC_DEFAULT_HAIKU_MODEL = 'my-haiku'
```

先在网关创建这些示例模型名，或改成你已配置的名字，然后从同一个窗口启动客户端。
这些变量只影响当前 PowerShell 及它启动的进程，不会修改其他已打开的客户端。

- 档位名不是价格保证。如果把多个档位都指向昂贵模型，后台小任务也可能使用它。
- 候选里的「按 1M 上下文请求」会保存 `[1m]` 后缀。转发前去掉后缀，并补充 Anthropic 的相关 beta 头；已有其他 beta 值会保留。
- 这个开关只表达请求意图，不会让不支持长上下文的上游获得该能力。
- 没找到精确模型名时，网关可以按 `haiku / sonnet / opus / fable` 关键字，在同一接口内找唯一匹配的配置。没有匹配或匹配到多个时仍返回 404，不随便选一个。

## 重试与自动换候选

### 先分清三件事

| 设置 | 做什么 |
| --- | --- |
| 同站重试 | 按供应商设置，再向原站发送同一请求。 |
| 200 截断拦截 | 连着几次拿回「没有正文的 200」后，先扣住响应，还是空的就原站重发。 |
| 自动降级 | 原候选失败后，尝试这个模型的其他候选。 |
| 发呆超时 | 开始输出内容之后才计时：长时间没有新内容就中断；不在网关内因此重试或换站。 |

前三种都只能在还没向客户端输出内容时进行。**已经返回半段回复后，不会拼接另一个站点的回答。**
重复请求是否产生费用由上游决定，不能承诺客户端看不到失败就没有额外开销。

### 同站重试

供应商编辑框里的 JSON 规则示例：

```json
[{"status":400,"times":2,"delay_ms":0},{"status":503,"times":2,"delay_ms":300}]
```

`status` 是触发状态码，`times` 是最多额外重发次数（上限 10），`delay_ms` 是重试前等待毫秒数。
连接失败按 502 检查规则；未配规则就不做同站重试。规则用完才考虑换候选。
400/422 由普通自动降级换下一个候选（见下表），也可以由明确配置的同站规则先重试。
间隔期间仍响应客户端断开和实时页的手动中断；手动停止记 `manual_abort`，不再重试或换站。

### 200 截断拦截

针对的是**状态码 200、正文却一个正文字节都没有、也没有完成事件**的响应。真库里
anyrouter / AgentRouter 这类公益站排队排不进去时就是这样：正文是一段和请求无关的错误信封
（`rate limit exceeded: ... exceeded token limit`），网关如实转发，客户端（codex）只看到
「流被截断」，它自己重试几次全是这一段，于是整轮停在半路要人手动继续。

同站重试认的是状态码，这种情况状态码是 200，规则匹配不上；自动降级又只能在「还没往下游
发过字节」时做，而截断要等整条流读完才知道。所以它两个都不是，落点在**先扣住再决定**。

供应商编辑框里的配置示例（空 = 关）：

```json
{"after":2,"times":3,"delay_ms":0}
```

- `after`：同一份请求（请求体指纹相同）连着几次「2xx + 没有完成事件 + 没有正文字节」
  之后开始拦截。默认 2。
- `times`：每次拦截最多在原站再发几把，默认 3，上限 10。用完仍拿到空响应就把最后一次
  原样交给下游，不无限重发。
- `delay_ms`：重发间隔毫秒。
- `same_body`：默认 `false`。置 `true` 时，要求那几次的**响应字节完全相同**才拦截。
  默认不要求 —— 错误信封里常带 request id / 时间戳，逐字节相同很容易永远不成立；
  「连着几次 200 且一个正文字节都没有」本身已经是很窄的签名了。

扣住的开销控制在一个字上：**一见到正文（或完成事件）就放行**。正常流式第一个字一到就交给
下游，不额外增加等待；只有那种一个正文字节都没有的空响应会被读到上游 EOF。所以：

- 半截回答不会被悄悄换成另一份 —— 正文一旦出现过就直接转给下游（原来的行为）；
- 扣住期间上游明说失败（error / response.failed）就地收手，不必把整段读完；
- 单次扣住有 8MiB 上限，到顶就当作「这不是那种短错误信封」，交出去实时转发。

状态只在内存里，键是「分组 + 请求体指纹」：重启即忘，和分组冷却一样；一份请求踩到的
串不会牵连别的请求体。当前记住的几串可以在 `GET /admin/api/failover` 的 `truncation`
字段里看到（页面上没有位置，给排查用）。这些都不写库。

被扣住又决定重发的那一次在转发记录里记 `hold_retry`；客户端看到的那条尝试序号不变，
因为它不算换候选。

它和同站重试一样是**原站行为**，不是换候选，所以带 `store` / `previous_response_id`
的请求照样会被扣住重发（「有副作用的请求不降级」那条限制管的是换站，管不到这里）。
重发是否让上游多算一次、留下两条记录，由上游决定 —— 这一点和同站重试完全一样，
不能承诺客户端看不到失败就没有额外开销。

默认值 `after=2` / `times=3` 是照着真库里的形状配的：这两站的失败都是「连着空几次、
然后某一发突然就好了」（96 组里 52 组在客户端自己重试的次数内恢复过），而没能恢复的
那些几乎都停在**连空 6 次**上 —— 那正是客户端自己的重试上限。`after=2` 让守卫在客户端
第 3 次请求时生效，`times=3` 让那一次请求一口气吃掉第 3~6 次上游尝试，于是客户端不用
再自己数到 6。每次空响应要等好几秒的站（或配额紧张的站），把 `times` 调小更划算：
它换来的是「一次客户端请求等更久」和「更多上游调用」。

### 自动换候选和冷却

默认只有 Anthropic 开启。策略常量在 `gateway/failover.py`：

- 一次请求按顺序把配置的候选都试一遍，同站重试次数另算。
- 已耗时超过 180 秒，或客户端已断开，不再开始下一次候选尝试。**180 秒不是整条请求的硬超时。**
- 从保存的首选和配置顺序解析候选，排除停用项；允许自动换候选时，冷却中的分组往后排。
- 分组连续失败 2 次，首次冷却 90 秒，再失败翻倍，最长 10 分钟。仍有未冷却候选时优先用它们；全部冷却时仍会尝试，不直接因冷却返回错误。
- 手动点击候选会清掉该分组的冷却。自动切换不会改写你保存的首选；重启会清空内存里的冷却状态。

| 失败 | 处理 |
| --- | --- |
| 404 | 当作该候选的模型/路径不可用，尝试下一候选，不据此给整个分组计失败。下一条可以是同组的另一个模型名。 |
| 401、403、408、413、425、429、500、502、503、504，以及代码列出的部分 52x | 记分组失败；换候选时跳过本次已失败分组的其他候选。若配置了同站重试，先执行它。 |
| 400、422 | 换下一个候选试试（有的站不支持某个参数或模型映射和别家不同），不算分组故障；同站规则可单独配置。 |
| 已开始输出后断流 | 记录异常，不重新拼接另一份回复。 |

**重要例外：**当前代码只要发现 `store` 或 `previous_response_id` 的值不是 `null`，就禁止换候选。
这包括 **`store: false`**，并不只包括 `store: true`。同站重试是独立规则，不能把这条限制理解成“所有重试都关闭”。

### 等待时间

`upstream.py` 的 httpx 超时设置是：连接 8 秒、读取 600 秒、写入 60 秒、等待连接池 600 秒。
连接超时不等于“8 秒内必须收到模型回复”。

另外有默认 20 秒的「发呆超时」：流式要开始出正文、推理或工具参数之后才计时，非流式从第一块正文起算，
每来一块续一次期；等响应头和等第一个字都不打断。
它会中断该请求，不自动换候选、不增加分组失败；`0` 关闭，最大可设 3600 秒。
慢模型可能正常等待较久，需要结合实际情况调整，不能只凭等待时间判断故障。

## 整条链交给另一个模型

一个下游模型可以把**整条链交给另一个下游模型**：`my-chat` 挂上转发之后，请求不按它自己的候选走，
而是按目标模型的候选链走（含目标的候选顺序、断路器冷却和自动换候选）。表是 `model_forwards`，
一个「模型名 + 接口」一行。

- **同接口内才生效**。转发按「模型名 + 请求接口」选链，跨接口的请求本来就互相看不见。
- **写入时校验**：不能绕成环、不能超过 `FORWARD_MAX_HOPS`（16）跳、目标最终必须在同接口下有候选，
  否则是「转过去也是 404」，写入时就拒掉（`ForwardCycle` / `ForwardMissingTarget`，都返回 409）。
- **多跳是允许的**：`a → b → c`，其中 a 和 b 都可以一个候选都没有（纯转发模型）；
  它们照样对下游暴露，`resolve_chain` 会一路跟到落地。
- **自己的候选保留但不参与路由**。取消转发（删掉那一行）立刻回到自己的候选链，
  所以管理接口里转发中的模型不报 `active_route_id`，前端顺着 `forward_to` 看目标的状态。
- **删除模型时**只删自己的转发，不动指向它的那些：目标没了就显示成断链，由人决定取消还是改指 ——
  静默把别人改回自己的候选比断链更难排查。
- 解析时还有一层兜底：万一库里被手改出一条环或超长链，`_forward_walk` 返回 `None`，当作无链处理，
  绝不死循环。

管理接口是 `POST /models/forward` 和 `DELETE /models/forward`（用 query 参数定位，模型名可能带 `/`）。

## 编排画布

侧栏「编排」把「上游站点」「模型路由」里的配置画成一张可拖动的图。它**只表达三件事**，
维护时按这个边界判断改哪里：

1. **下游气泡** = 一个「模型名 + 接口」= 一条链。
2. **候选环（轮盘）** = 绕气泡一圈的端口就是这条链的候选，**顺时针就是自动降级的尝试顺序**；
   指针指向的那条是「现在实际会先打的」（`active_route_id`），空心小圈是首选（`preferred_route_id`）——
   冷却把流量拨走时两者会分开，这正是「被跳过了」的显示。
3. **箭头** = 上游节点连到端口是「这条上游挂在这个模型上」，气泡连气泡是「整条链交给它」。

两条定死的规矩，改代码前先确认没破坏它们：

- **顺序只有一个出处：环。** 箭头永远不表达顺序，所以调顺序是拖端口，不是挪箭头。
- **拨盘只「选」，不改结构。** 指针转到哪个端口就切到哪条；改真名、删候选走端口菜单。

几个容易踩的坑，都在代码注释里标了，这里列出来免得被"顺手优化"掉：

- **指针必须是常驻 DOM 节点**，不能被整块 `innerHTML` 重建 —— 它一变就重建的话旋转过渡永远来不及播，
  而「自动降级」正是靠这根针转过去看出来的。所以气泡的骨架建一次，只改 `.cv-ports` 和 `.cv-core`。
- **针尖要站在环外面**（`KNOB_OUT`）。和端口同半径时，端口在 DOM 里排在指针后面会盖住针尖，
  拖到的就成了端口（变成调顺序），拨盘根本拨不动。
- **`.cv-needle` 是个 `<button>`**，必须显式清掉浏览器的默认底色和边框，否则那圈灰底会盖住整个气泡。
- **SVG marker 要写 `markerUnits="userSpaceOnUse"`**。默认是 `strokeWidth`，箭头会跟着线宽放大，
  粗的交接箭头会长成一个大三角。
- **切换视图用的是 View Transition**，DOM 变形发生在下一帧的回调里。刚 `showView` 完就量画布尺寸会量到
  `0×0`，算出来的缩放会掉到下限、把所有节点叠成一团。`fitCanvas` 因此会在量不到尺寸时放弃并留到下一帧重试。
- **缩放下限 0.45**。再小的话相邻端口在屏幕上会叠到一起，点哪个都点不准。
- **首次自动框的是气泡，不是全部节点**（`FIT_MIN = 0.62`）：上游节点是参考层，为它一列竖排把缩放压到 0.5
  以下，字就全糊了。用户点「适配」才连上游一起框。

坐标是**纯展示状态**，单独存在 `settings` 表的 `canvas_layout` 条目里（不动 schema），
读写走 `GET`/`PUT /admin/api/canvas-layout`。节点键的格式在 `gateway/canvas.py` 和 `web/canvas.js`
各写了一份，改一处必须改两处：
| 键 | 含义 |
| --- | --- |
| `m\|模型名\|接口` | 下游气泡 |
| `u\|分组 id\|上游真名` | 上游节点 |

坏坐标只丢自己（坏 JSON、越界数值、拆不出来的键都退化成自动摆放），节点数有上限（800）直接拒。
写入时会剪掉库里已经不存在的节点 —— 剪枝按「库里有没有」算，不按「界面上看不看得见」算，
所以某个接口被整体停用时位置留着，重新打开还在原处。画布坏了一份坐标绝不该影响转发，
这一点有 `test_canvas.py::test_layout_never_touches_routing` 盯着。

## 实时状态与统计

实时登记在内存中，包含等响应头、等内容和输出中三个阶段。结束记录保留 90 秒，最多 24 条。
异常残留的活跃项超过 12 分钟会在读取状态时清理，并写日志。

`count_tokens` 请求也会显示和参与转发处理，但不计入正常请求的“进行中”数量、转发记录和用量累计。

概览、健康和路由行次数共用所选时间窗，模型按「模型名 + 接口」聚合。热榜只展示前 8 名，
`GET /admin/api/overview` 仍返回全部模型链的统计，其他路由不会因此丢失次数徽标。
单独的 `/stats/series`、`/stats/upstreams`、`/stats/models` 接口已退役，避免重复维护同一份聚合入口。
`GET /admin/api/stats` 保留累计统计；页面快轮用 `?live_only=true`，只读内存活跃数、不扫请求记录。

### token 数怎么理解

- Token 是模型处理文本等内容时使用的计量单位，不等同于字符数或字节数。
- 上游提供用量时优先显示它的报告；带 `≈` 的值是网关根据历史比例估算的，**不能当作计费量**。
- 输入请求包含 JSON 结构、工具描述等，字节数和实际计费 token 不存在固定的一一对应关系。
- 输出估值根据收到的内容计算。上游可能不返回全部推理内容，因此可见内容量与上游报告的输出用量可能不同。
- `count_tokens` 显示的是上游返回的计数，也不是网关独立核验过的账单。

估算比例在 `stats.token_ratio()` 中计算，使用保留记录的中位数并缓存一分钟。
输出样本排除带推理内容的记录，用内容字节而不是完整 SSE/JSON 大小；样本差异过大时不显示估值。
比例异常只能作为进一步排查的线索，不能直接证明站点多收费。

### 转发记录怎么看

数据库最多保留最近 2000 条转发记录，管理页显示最近一部分，不是永久账本。
每次候选尝试单独记一条；“第 N 次”“已降级”用来说明重试经过。
成功率、缓存比例等计算见 `stats.py`，其中 Anthropic 的输入量需要合并缓存读取/创建等字段。

| 备注 | 含义 |
| --- | --- |
| `ok` | 该次转发按记录规则正常收尾。仍需一起看 HTTP 状态码；例如 500 的错误体也可能完整转发。 |
| `truncated` / 流被截断 | 没有识别到预期结束事件。可能是上游缺事件，也可能是压缩、格式或解析问题。 |
| `upstream_abort` / 上游断流 | 接收上游响应时连接异常中断。 |
| `client_abort` / 客户端断开 | 正常结束前客户端离开。 |
| `manual_abort` / 手动中断 | 用户在实时页停止了请求。 |
| `stall_timeout` / 卡住超时 | 开始输出内容后，超过设置时长没有新内容，被网关中断。 |
| `failed_over` / 已降级 | 这次失败后又尝试了其他候选。 |
| `hold_retry` / 截断重发 | 这一次是「200 但没有正文」，被截断拦截扣住没发给客户端，正在原站重发。 |

Responses 通过 `response.completed` 或独立的 `[DONE]` 识别结束；Messages 通过 `message_stop`，也兼容独立 `[DONE]`；Chat Completions 通过 `[DONE]`。
正文里提到这些词不算结束。上游已发结束事件、客户端随后离开，按正常结束处理。

Anthropic 的输入用量常在流开头，输出用量在结尾。转发统计保留头部 8KB 和尾部 64KB，修改这部分时不要只看流尾，否则长回复可能丢失输入用量。

## 代理和证书

出口属于供应商配置，普通转发和拉取模型列表都使用它。
连接按出口复用；“跟随系统代理”还会检查系统代理配置变化，避免新请求一直复用旧设置。

- 跟随系统：读取环境变量和 Windows 系统代理。
- 直连：关闭程序读取系统代理的行为（`trust_env=False`）。
- 指定代理：支持 HTTP、HTTPS、SOCKS5；SOCKS5 需要额外安装 `socksio` 到项目环境。
- VPS 预设：由设置项 `egress_vps` 提供；修改预设不会自动改掉供应商已保存的代理地址，需要重新选择。

回环地址在跟随系统和直连模式下不走隐式代理；明确指定代理时按指定值执行。
TUN 可以在系统网络层继续接管流量，需在代理软件里设置直连规则。
`vless://`、`shadowsocks://` 不能直接填入；需先由已有代理软件提供 HTTP/SOCKS 端口。

HTTPS 代理使用自签证书时，可以指定自己确认过的 CA 文件：

```text
https://user:password@proxy.example.com:8443#ca=data/proxy-ca.pem
```

这是格式示例，不是真实凭据。CA 的相对路径以项目根目录为准；保存时检查文件，连接代理时用于验证证书。
不要靠关闭证书验证解决连接问题。项目通过 `truststore` 使用系统信任的证书；杀毒软件的 HTTPS 扫描也可能影响验证路径。

「测一下」会通过可用出口请求站点的模型列表地址。有 HTTP 状态码只证明能得到响应，401/403 不代表模型调用成功。

### 旧 VPS 部署备注

旧 README 记过一套具体部署：gost v3.3.0、服务名 `gost-proxy.service`、端口 8443，TLS 证书放在服务器 `/etc/gost/`，本机 CA 文件为 `data/vps-proxy-ca.pem`。
**本次没有登录服务器核实，可能已经变化**，它也不是使用网关的必需配置。

按那套部署改端口或密码，需要同时核对服务启动参数、设置项 `egress_vps` 和各供应商已保存的出口；更换证书还需更新本机 CA 文件。
旧记录还提到代理软件用名为 `vps-direct` 的覆写让 VPS 地址直连，规则形如 `IP-CIDR,<VPS-IP>/32,DIRECT,no-resolve`。
换 IP 后要检查那条规则是否仍有效，不能假定“网关选直连”就一定绕过 TUN。

## 抓包排查

抓包是在本机临时保存请求和响应，用来查“上游说正常，客户端却没收到”的问题。
**先确认隐私风险：请求正文、工具参数、回复都可能含密钥或私人内容，不会自动脱敏。** 只在需要时开少量，分享前逐项检查。

网关已启动、项目目录中已有 `data/` 时，在 PowerShell 执行：

```powershell
# 记录下一条请求，不需要重启
Set-Content -LiteralPath '.\data\capture-stream.flag' -Value '{"max":1}' -Encoding utf8
```

把 `max` 改为 `3` 可以记录三条。名额可能被其他并发请求占用，复现时尽量避免无关请求。
提前关闭可调用管理接口：

```powershell
Invoke-RestMethod -Method Put -Uri 'http://127.0.0.1:8317/admin/api/capture-stream' `
  -ContentType 'application/json' -Body '{"enabled":false}'
```

关闭表示不再开始新的抓包；已经开始的一条仍可能写到请求结束。抓满后自动关闭，**已生成的文件不会自动删除**。

输出在 `data/captured_stream/` 下的时间戳目录：

| 文件 | 内容与限制 |
| --- | --- |
| `request.json` | 客户端原始请求体，不是已做模型改名/文本替换后的版本。正文不脱敏。 |
| `stream.sse` | 转发循环读到的响应字节，可能已经解压，并非网络线路上的原始压缩包；文件名不保证内容一定是 SSE。 |
| `meta.json` | 模型、上游、状态码、请求/响应头、字节数、是否识别到结束事件等。 |

常见鉴权头会被过滤，但未知头、正文和响应仍可能含秘密，不能承诺“密钥一律不落盘”。
响应文件上限 16MB；超出后只停止继续写响应文件，不影响转发。这个上限不等于整个抓包目录的大小上限。

建议按顺序看：

1. `meta.json` 的状态、`content-type`、`content-encoding`。
2. `stream.sse` 实际是文本、压缩内容还是错误消息；必要时交给合适的解码工具检查。
3. 是否有该接口的完成事件，再与客户端报错时间对照。

管理接口 `GET /admin/api/capture-stream` 看开关状态，`GET /admin/api/capture-stream/list` 列出抓包目录。
另有 `data/capture.flag` 的一次性请求头诊断，会写 `data/captured_headers.json` 等诊断信息；同样不应未经检查就公开。

压缩诊断单独由 `data/compaction_capture.flag` 开启，结果写入 `data/compaction_capture.json`：
只记请求形状、事件类型和不透明内容的长度，不保存该内容原文；没有发现时继续等待，发现后收旗。
普通转发不递归扫描压缩条目；流式抓包只额外计数事件类型，压缩扫描仅在自己的开关开启时运行。
这只能证明观察到相应条目，不能单凭它宣称客户端后续复用成功。

## 请求文本替换

管理页「上游站点 → 敏感词绕行」用于处理**已确认的固定文本误报**：

```json
[{"from":"<已确认误报的原文>","to":"<保留原意的替代写法>"}]
```

- 规则目前是**全局的**，不是某个供应商独有；会作用于转发请求中的所有字符串值，包括模型名、消息和工具参数等。
- `to` 为空字符串表示删除；空规则表不改内容。
- 匹配的是字面文本，不是正则。不要使用很短、很常见的词，否则会误改正常内容。
- 这不是密钥脱敏，也不能预先识别上游所有审核规则。
- 触发文本只放在规则配置里，文档、代码、测试和提交说明使用占位符。

`dev/find-sensitive-line.py` 可以帮助定位误报，但**不是只读检查**：它会向真实上游重复发请求，可能计费；还会临时清空全局替换规则，正常收尾时再恢复。
不要和日常请求同时使用。被强制停止后，要人工核对规则是否恢复；它打印的内容也需要保密。

确认需要再运行，例如：

```powershell
& '.\.venv\Scripts\python.exe' '.\dev\find-sensitive-line.py' '<本次抓包目录>' --max-calls 20
```

`--max-calls` 限制请求次数；`--chunk 1` 改为逐行检查，可能增加调用量。
找到一处后必须重新检查整段文本，因为可能存在多个触发点。没有证据时，不要把整类符号或普通文本全部替换。

## 数据与备份

- 主库是 `data/gateway.db`；供应商、分组 Key、候选、设置和转发记录都在这里。不要操作仓库根目录里可能残留的同名文件。
- 当前代码的数据库版本号是 8，以 `db.SCHEMA_VERSION` 为准。旧版协议转换留下的兼容字段不代表转换功能仍可用。
- 需要升级旧库时，程序先通过 SQLite 的备份接口生成 `data/gateway.db.bak-<时间戳>`，自动保留最近 3 份迁移备份。它不是定时备份，也不能代替自己保留的重要备份。
- 运行中的 SQLite 可能还有 `-wal` 文件，**不要只复制正在使用的 `gateway.db` 就当作完整备份**。使用 SQLite 备份方式，或正常退出后再备份需要的数据。
- 文本日志 `data/gateway.log` 每份 5MB，轮换为 `.1`、`.2`，共保留三份。启动异常还可能写 `data/crash.log`。
- 数据库、备份、代理配置、证书材料和抓包都按敏感文件对待；尤其不要提交真实 Key 或代理密码。

## 启动与端口

`main.py` 只监听 `127.0.0.1`。所有路径都拒绝浏览器发来的跨站请求（不止管理接口 —— `/v1` 被别的网页借去调用会花你的钱），
管理接口还要求 Origin 和网关地址（含端口）完全一致，Host 只接受回环写法、缺 Host 也拒绝。
这些检查挡的是「别的网页借浏览器打本机」，不是账号鉴权，仍然不要开放给其他设备。

列表接口不下发完整密钥和代理凭据（分组 Key、出口地址都是脱敏形状）；
编辑弹窗打开时才按需取回原文（`/admin/api/groups/{id}/key`、`/admin/api/upstreams/{id}/egress`、`/admin/api/egress-presets/vps`）。
列表上的启用开关走 `/enabled` 专用端点，只翻那一列，不用整包 PUT 覆盖别的字段。

- 双击 `start-gateway.bat` 默认端口 8317，会打开网页；托盘菜单可设置开机自启或正常退出。
- 临时改启动脚本的端口：`.\start-gateway.bat 9000`。
- 直接运行 `main.py` 时，可通过 `--port` 指定；未指定时读取 `data/settings.json` 的 `port`。编辑已有设置文件时保留其他内容。
- **启动脚本会显式传端口**，所以只改 `settings.json` 不会改变双击脚本的默认端口。
- Windows 托盘模式有单实例检查。虚拟环境的 `pythonw.exe` 出现父子两个进程可能是正常启动方式，不等于开了两套服务。
- 优先用托盘「退出」；前台模式用 `Ctrl+C`。管理接口也提供 `POST /admin/api/shutdown`，不要在有重要请求时调用。

## 测试怎么跑

以下命令在项目根目录的 PowerShell 执行，使用已有 `.venv`。没有环境先按[首页](../README.md#开始使用)安装。
先按改动选文件或用例，通过后停止；有新改动、失败或跨模块风险才扩大范围。
不为整理文档运行整套测试，不因“保险起见”补跑全量，也不把历史报告的数量写成当前结果。

### 日常按改动检查

例如只改画布坐标，跑对应文件；默认排除需要真实监听端口的 `network` 用例：

```powershell
$env:PYTHONUTF8 = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
uv run .venv\Scripts\python.exe -m pytest tests/test_canvas.py -q -p no:cacheprovider --durations=5
```

| 改动范围 | 首选检查 |
| --- | --- |
| 画布坐标、模型批量添加 | `tests/test_canvas.py` 或 `tests/test_model_batch.py`；界面同时改动时加 Node 测试。 |
| 路由、模型转发 | `tests/test_routing.py`、`tests/test_forwards.py`，以及改动涉及的 `test_proxy` 用例。 |
| 重试、冷却 | `tests/test_same_retry.py`、`tests/test_failover.py`；取消等待还需相关 `test_lifecycle` 用例。 |
| 200 截断拦截 | `tests/test_truncation.py`；改动扣住/重发的落点时加对应 `test_proxy` 用例。 |
| 请求转发、协议事件解析 | `tests/test_proxy.py`、`tests/test_lifecycle.py` 和 `test_units.py` 中对应函数；连接语义另跑下面的网络检查。 |
| 统计、实时状态 | `tests/test_stats.py` 或 `tests/test_inflight.py`；取消真实流需 `--network`。 |
| 调度观测、采集器 | `tests/test_learning.py`；改了转发挂接点时加对应转发/生命周期检查。 |
| 管理接口、数据库迁移 | `tests/test_admin.py` 中对应用例；跨模块数据库结构变动最后做完整检查。 |
| 出口、TLS、客户端缓存 | `tests/test_egress.py` 和 `test_units.py` 中对应用例；真实代理/TLS 路径加 `--network`。 |

pytest 的文件路径、`::test_name` 和 `-k` 可进一步缩小范围。需要整个非网络组时才省略文件路径；默认组也不是每次小改动的必跑清单。

### 涉及真实连接的检查

流中切换、客户端断开、代理和 TLS 等，需要本机真实连接及模拟服务：

```powershell
uv run .venv\Scripts\python.exe -m pytest tests/test_proxy.py tests/test_inflight.py --network -q -p no:cacheprovider --durations=10
```

`network` 在这里指本机网络测试，不是去请求真实供应商。
上例针对流生命周期；出口改动可换成 `tests/test_egress.py tests/test_units.py`。省略文件路径会执行整个网络组。

### 有明确理由时做完整检查

共享 fixture、测试选择入口、跨模块数据库/转发重构，或用户要求完整验收时，最后执行一次：

```powershell
uv run .venv\Scripts\python.exe -m pytest --full -q -p no:cacheprovider --durations=15
```

默认组和网络组互不重复，合起来覆盖完整测试。已验证完两组就不再追加第三遍全量。
`--full` 和 `--network` 不能同时使用；原来的 `-m network` 仍兼容。其他 `-m` 条件在所选组内继续筛选，
`--full` 也不会清除文件路径或 `-k` / `-m`，做完整验收时不要携带这些过滤条件。
终端会显示所选范围和 deselected 数量；默认运行通过只能报告非网络组通过。

### 前端检查

没有 npm 构建步骤，直接检查原生 JavaScript：

```powershell
Get-ChildItem -LiteralPath '.\web' -Filter '*.js' -File | ForEach-Object {
    node --check $_.FullName
    if ($LASTEXITCODE -ne 0) { throw "JavaScript 语法检查失败：$($_.Name)" }
}
npm --prefix web test
git diff --check
```

| 测试文件 | 主要检查 |
| --- | --- |
| `test_proxy`、`test_lifecycle` | 转发、模型与请求头、分块、结束判定、中断收尾。 |
| `test_routing` | 候选选择、停用、同名多接口隔离和配置冲突。 |
| `test_admin` | 管理接口、保存校验、模型目录、数据库升级。 |
| `test_model_batch` | 批量添加模型：名字相似度分级、扫描不写配置、单站失败与其他站隔离、提交幂等与跨接口各一条链。 |
| `test_forwards` | 下游→下游转发：多跳、成环与死链校验、候选保留和恢复。 |
| `test_canvas` | 编排画布坐标：存取、剪枝、坏输入退化，以及「坐标不影响路由」。 |
| `test_failover`、`test_same_retry` | 换候选、冷却、同站重试及限制。 |
| `test_truncation` | 200 截断拦截：武装条件、扣住与重发、次数上限、见到正文即放行、配置校验。 |
| `test_stats`、`test_inflight` | 用量、成功/失败统计、实时状态和取消。 |
| `test_learning` | 调度元数据、请求/尝试关联、事件时间线、取消、容量限制及采集故障旁路。 |
| `test_egress`、`test_units` | 代理、证书、工具函数与内容观察。 |
| `web_protocols.test.mjs`、`web_app.test.mjs` | 协议选项、刷新队列、弹窗会话、模型列表重开与统计展示。 |

测试使用临时数据库和模拟上游，不拿真实 `data/` 做演练。为了提速不能删必要断言、隐藏失败用例，或修改正式运行的超时/重试参数。
通用 `gateway` fixture 关闭采集线程；`test_learning` 自己开启真实采集器验证写盘与转发挂接。
普通模拟流不做无意义的逐块延时；真实网络流保留原有时序。挂起的模拟上游只在用例断言结束后释放，并检查服务线程确实退出。
统计样本批量写入，参数检查不额外创建 TLS transport；真实代理和证书仍由网络组覆盖。
语法检查不等于浏览器验证，模拟转发通过也不等于真实站点具备某项能力；报告时分开写。

### 编排画布的浏览器检查

上面的语法检查看不出画布对不对 —— 端口位置、拖拽、拨盘都需要真实浏览器。
这两个脚本用**独立临时库和假站点**，不碰日常那份配置：

```powershell
# 一个终端：起一个独立实例（临时库在 dev/.canvas-preview/）
& '.\.venv\Scripts\python.exe' dev/preview-canvas.py --port 8331
# 另一个终端：跑验收，截图写到 dev/canvas-qa/
node dev/check-canvas.mjs 8331
```

加 `--empty` 起的是**不造任何数据**的实例，用来看全新用户第一次打开的样子（画布和上游池都是空的）。

`check-canvas.mjs` 会走一遍四个核心操作并核对后端：点端口切换、拨盘切换、拖端口调顺序、
从上游池拖拽挂候选（含重复挂载不生效）、挪动坐标落库并在刷新后保持、右键菜单与交接弹窗、滚轮缩放。
拖拽用 CDP 的真实鼠标事件（`Input.dispatchMouseEvent`）—— 合成的 `PointerEvent` 走不了浏览器的指针状态机，
拖拽用例用它等于没测。断言里比较位置时一律换算回**世界坐标**，不要拿屏幕坐标直接比：
前面的 `scrollIntoView` 可能把整页滚下去，刷新后滚动位置复位，屏幕坐标就会平白差几十像素。

### 批量添加模型的浏览器检查

```powershell
# 一个终端：起一个实例（真实 data/ 也行，脚本会自己清理它建的东西）
& '.\.venv\Scripts\python.exe' main.py --port 8399 --no-tray
# 另一个终端：跑验收，截图写到 dev/batch-0*.png
node dev/verify-batch-add.mjs 8399
```

它自己建一个临时上游（名字固定为 `__batch-verify`）+ 两个分组，一个放**完全同名**的模型、
一个放只沾一部分的名字，然后在页面上扫描、核对默认勾选、提交、再提交一次验幂等，最后把上游删掉
（候选随分组级联下线）。用真实 `data/` 跑时那一轮扫描真的会去请求你自己的所有上游 ——
慢站会让它停在 25 秒预算上，属于预期。
扫描要真的问一圈，所以这个脚本每次跑大约半分钟，别用它替代语法检查。

## 调度学习数据采集

新启动的进程默认将调度元数据写到 `data/learning/`：最多 128 MiB、按文件保留 30 天，
与最近约 2,000 条请求日志分开。后台写入，不保存正文、工具参数、密钥或完整请求头；
但模型名称、时间和用量仍属于本机私有数据。它不会修改现有超时、重试或降级设置。

`GET /admin/api/learning-status` 查看是否开启、写入时间、队列和丢失/错误计数。
启动前设置 `MODEL_GATEWAY_LEARNING=0` 可以关闭；已经运行的进程需要正常重启才加载新代码或开关。
无需迁移数据库。只读汇总命令、字段口径、数据限制和以后怎么训练见
[调度学习：采集与后续设计](learning-scheduler.md)。

训练、模型影子运行和自动接管都**尚未实现**；不要把采集动作当作启用了智能调度。

## 修改前端时注意什么

- 浏览器直接加载 ES 模块。`/static` 使用 `cache-control: no-store`，避免新旧模块混用。
- 供应商、分组和候选弹窗每次打开都是新会话。迟到的结果、错误、刷新和 close 事件不能改新会话，即使两次打开的 id 相同或都是新建。
- 保存目标与表单值在第一次等待前固定；写成功后先失效正确的缓存，恢复修改当前弹窗前再核对会话。模型列表的 busy 只用于提示，同会话由请求键去重，不能挡住关闭重开后的新请求。
- 保存完成后的刷新，必须读取保存后的数据，不能拿保存前已发出的旧请求充数。
- 同一类刷新不要重复堆积；不同入口更新同一份状态时也要防止旧结果覆盖新结果。
- 保留未保存的表单输入。模型勾选立即生效，组名/接口/Key 需要保存，这两种操作不要混淆。
- 非实时页每 3 秒只取内存活跃数；实时页用 1 秒 `/inflight` 刷新，不再叠加 3 秒轮询。每 15 秒更新配置/概览/记录；隐藏标签页或打开弹窗时暂停后台轮询。卡片计时在本地更新。
- 确认框使用独立 `<dialog>`，提示条使用 `popover`，都需要显示在当前弹窗上方，不能只靠普通 `z-index`。
- 按钮的可用性由业务状态决定时（批量添加模型那个按钮一次点击里先扫描后提交），
  要设 `el.dataset.locked`：`run()` 收尾会无条件重新启用元素，不设的话按钮看着能点、点了什么也不发生。
  这类「加过的行」状态要放在模块变量里而不是只写 `dataset` —— 提交后的刷新会把列表整个重画。

改完按实际影响验证，不为了文件数量或抽象层数重写整个前端。
