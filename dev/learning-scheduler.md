# 调度学习：采集已实现，训练与接管留待以后

这是自己使用的网关实验，不是课设，也不是要重写调度系统。

**当前只采集元数据，不训练模型、不推荐动作、不改变超时、重试、候选顺序或降级开关。**
后续步骤都是设计，不会因为这份文档而自动执行。没有定时任务，也不会自动调用供应商做实验。

## 1. 现在怎么用

正常启动新版本后，采集默认开启，文件位于 `data/learning/`，与 `data/gateway.db` 的约 2,000 条滚动日志无关。
已经运行的旧进程不会热加载这些代码；等空闲时正常退出并重新启动即可，不需要迁移旧库。

- JSONL：每行一条 UTF-8 JSON 元数据记录。
- 单文件最多 8 MiB，跨 UTC 日期换文件，总容量最多 128 MiB。
- 按文件最后写入时间保留 30 天，至少每分钟做一次维护；容量先到就先淘汰旧文件。
  这是文件粒度保留，不是保证每条记录恰好保存满 30 天。
- 只管理 `data/learning/events-日期-随机ID.jsonl` 格式的自有文件，不删除目录里的其它文件。
- 日常转发只入有界内存队列；后台线程批量写入。队列最多 128 条，每条最多 128 KiB。
  队列满、记录过大或写盘失败时丢采集记录，**不等待磁盘，不更改转发结果**。
- 每次尝试最多保留最近 256 个事件窗口。相邻同类事件在 250ms 内合并，保留首尾时间和计数。
  超限记录 `windows_dropped`，不是偷偷把截断时间线当完整样本。
- 正常退出给后台写入最多 3 秒收尾；强杀、断电、长期阻塞的磁盘可能丢尾部。不是审计日志。

### 看看采集是否正常

运行中的状态：`GET /admin/api/learning-status`，继承网关已有的本机访问限制。

重点看：

| 字段 | 含义 |
| --- | --- |
| `enabled`、`writer_alive` | 是否启用、后台线程是否存活；线程存活不代表写盘成功。 |
| `queued`、`written` | 等待写入的记录数、已经写入的记录数，不是请求数。 |
| `dropped` | 被丢弃或因部分批次失败而不确定是否写入的记录数，保守计数。 |
| `errors`、`last_error` | 采集故障数量和异常类名，不记录异常消息。 |
| `last_write` | 最近成功写入时间，UTC。 |

后台约每分钟及退出时写 `collector_status`，保留每个 `run_id` 的损失计数。
磁盘完全不可写时状态记录本身也无法保存；仍需查看实时接口，不能把缺少报错文件理解为没有错误。

只读汇总，不访问供应商、不改库、不启动服务。在项目根目录执行：

```powershell
uv run --offline --no-project --python '.\.venv\Scripts\python.exe' python dev/learning-report.py
```

没有数据会返回零，不会创建目录。在线读取可能碰到尚未写完的尾行；报告会计入 `bad_lines`，
需要稳定导出时先正常退出网关，再复制这一个目录。脚本不会替你导出或上传文件。

### 关闭采集

在启动网关的同一个 PowerShell 窗口设置：

```powershell
$env:MODEL_GATEWAY_LEARNING = '0'
uv run --offline --no-project --python '.\.venv\Scripts\python.exe' python main.py
```

`0`、`off`、`false` 都表示关闭。恢复时移除该环境变量或设为 `1`，再正常启动。
环境变量只在启动时读取；关闭不清空历史文件，也不会继续执行保留期清理。
从托盘或快捷方式启动时，以那个进程实际继承的环境为准。当前没有新增 UI 开关。

## 2. 记录什么、不记录什么

记录已进入上游转发流程的普通请求；无候选、非法输入、接口停用等入口拒绝，以及
`count_tokens` 元数据请求不记录。没有采集的请求不纳入本数据集的总量或失败率分母。

记录：

- 协议、固定接口路径、客户端类别、请求大小、是否流式、是否含有状态字段。
- 客户端模型别名、真实模型名（各最多 128 字符），供应商/分组/候选的本地数字 ID。
- 当时的有效降级资格、停滞阈值、新尝试时间预算、最多前 64 个候选 ID 及实际候选数量。
- 请求与尝试关联、等待时间、内容事件时间、结束和取消原因、尝试动作、计划重试延迟。
- 开始尝试时同组的其它受采集尝试数；不是供应商实际并发，也不包含未采集请求。
- 上游返回的用量数字；没有就记空，不估成真实账单。

**不记录**请求/响应正文、提示词、输出、工具参数、推理内容、完整请求头、密钥、URL、
客户端会话 ID、正文哈希或异常消息。心跳内容和未知 SSE 事件名也不保存。
现有临时抓包功能是另外一套机制；主动开启抓包依然可能保存正文，不能把本采集层的限制套到抓包上。

这不是“可以随便公开的数据”：模型别名、时间、大小、用量和故障分布仍能暴露使用习惯。
文件沿用本机目录权限，不额外加密，留在本机即可。

### 关联与时间

每行包含 `schema_version`、`run_id` 和 UTC `ts`：

- `run_id`：一次进程采集器生命周期的随机 ID，重启变化。
- `request_id`：一次进入网关的请求的随机 ID，不从正文或客户端标识派生。
- `attempt_id`：`request_id:attempt_seq`，**每次进入上游发送尝试**递增，包括同站重试。
  连接准备也可能失败，计入一次尝试不保证请求已经到达上游。
- `candidate_attempt`：兼容现有候选尝试序号，同站重试可能不递增，不能代替 `attempt_seq`。
- `request_start → attempt_start/attempt_end × N → request_end`；中途可能穿插其它请求。

`t_ms`、`start_ms`、`headers_ms`、`first_byte_ms`、`first_content_ms`、`last_content_ms`、
`end_ms` 和窗口首尾时间，全部是相对同一次 `request_start` 的单调时钟毫秒数。
请求起点在解析和候选选择之后，**不包含客户端上传和前期校验**。
某次尝试的响应头耗时应计算 `headers_ms - start_ms`，不能直接把 `headers_ms` 当本次连接耗时。
响应头等待包含连接、上传到上游和上游处理，当前不能拆成 DNS/TLS/模型计算时间。

网关自己做的重试能准确关联；客户端断流后再次发起的请求没有可靠关联标识，
**不能自动合并成同一次用户任务**。数字路由 ID 也不是跨数据库恢复/重建永久有效的身份。

### 时间线与结果

事件类别只有固定枚举：

- `content`、`reasoning`、`tool`：现有观察器识别到的内容进展，统称有效内容。
- `heartbeat`：SSE 注释或 ping，不续算有效内容时间。
- `metadata`：其它可解析的开始、用量等事件。
- `completion`：识别到现有协议支持的结束标记。
- `protocol_error`：显式 error、Responses failed/incomplete，或 JSON 显式错误状态。
- `malformed`：观察到的非 JSON 数据；可能是协议兼容问题，不能直接叫上游故障。
- `observation_error`：现有流/JSON 观察过程发生异常，只标记不保存异常消息。
- `body`：非 SSE 字节到达，不宣称它已构成完整语义内容。

这是**网关收到并解析完事件的时间**，不是供应商生成 token 的时间。
网络可能合并多个事件，窗口又会合并相邻事件；不能用它计算精确的逐 token 延迟。
`text_bytes` 沿用观察器的计数口径，只作特征，不是账单 token。

尝试结尾保存完整期内的内容计数、最长内容间隔、恢复过的 ≥5 秒内容停顿次数、
末尾静默时长，以及有限的窗口尾部。首内容之前的等待与内容之后的停顿必须分开分析。
`planned_delay_ms` 只是策略计划，真正延迟看下次尝试起点；有计划不代表真的重发了。
`action` 记录规则已经选择的动作，不是“最佳动作”标签。

`http_status`、`note`、`completion_seen`、`protocol_error_seen` 分开存：

- `note=ok` 可能伴随 HTTP 500，不能直接作成功标签。
- HTTP 200 也可能带协议错误或缺少结束事件。
- `interrupted=true` 表示手动取消、客户端取消、停滞策略中断、内部异常或未观察完；不是“确实卡死”。
- 手动打断的 `manual_reason` 目前是 `unknown`，未猜测人的意图，尚未新增原因录入 UI。
- `observer_oversized_frames`、`malformed` 和 `observation_error` 标记观察质量；零值也不是格式完全正确的证明。
- `request_end` 另记响应头是否发出、已发送的 `response_status`、ASGI 已成功发送的正文量、正文发送是否结束及 `delivery_note`。
  上游完整、网关发送成功和客户端最终任务成功是不同概念，当前没有最后一项反馈。

少了起点或结尾可能是正在运行、容量轮转、写盘丢失或进程退出。必须先检查完整性，
不能把孤立记录补成负样本。关闭后重新开启也不是完整连续观测。

## 3. 下次想继续时，按这个顺序

### A. 检查数据，而不是按天数宣布够训练

先运行汇总脚本，看：

1. 采集是否真正写入，有没有丢失、坏行、未知 schema 或大量缺起止的请求。
2. 数据是否跨多个日期、正常时段和异常时段，而不是一次故障的数百条重复请求。
3. 是否确实出现了“长停顿后恢复”的片段，而不只是 HTTP 失败和无首内容的截断。
4. 常用模型/协议/候选组合各有多少数据，哪些组合根本没被尝试过。
5. 时间线截断占比；事件窗口缺失的部分不参与精确恢复标签构造。

1–2 周只是一个可选检查点，不是训练门槛。只采到了某一站的一次事故，就继续使用原规则。
要研究更长跨度，应提前手动导出稳定副本；128 MiB/30 天并不保证无限保留。

### B. 第一个目标只做“继续等是否会恢复”

先区分两类任务，优先做第二类：

- 首内容等待：多久出现第一个有效内容。
- 内容后停顿：已经停了 `s` 秒，未来 5/10 秒是否恢复内容。

从完整时间线生成固定观察点，不只采“最后那次异常”：

- 输入只使用观察点之前的信息：协议/模型/候选、请求大小、已经等多久、此前内容间隔、
  已尝试次数、当时剩余时间，以及此前已结束的同组请求统计。
- 未来确实观察到恢复，可标恢复；观察窗口不够或被提前中断，标未知/删失，不强标“不恢复”。
- 正常完成、显式错误和自然 EOF 是另外的结束类型。正常完成不需要继续出字，
  不能因为未来没新内容就叫“卡死”。
- 250ms 合并窗口存在分辨率边界：观察点落在窗口内部时保守剔除或使用区间标签。
- 最终总耗时、最终状态、最终输出量、未来上游健康只用于结果，不作为中途输入。
- 旧 `request_log` 可做粗略统计，不与新时间线伪装成同一种训练样本。

### C. 先做基线，再决定是否值得训练

比较三种离线版本即可，暂不引入在线训练服务：

1. 原固定阈值规则；实际阈值取采集快照，不假定一直是默认值。
2. 按协议/模型统计正常内容间隔的简单规则，稀疏组合回退到更大的分组。
3. 一个小型监督模型，预测恢复概率。模型种类等看到有效样本分布再选。

训练、验证、测试按时间向后分割；同一请求、重试链和同一故障时段尽量放在同一边。
归一化、类别编码和阈值选择只用训练/验证段。禁止随机拆同一条流的窗口造成“提前看过答案”。

重点看误打断正常流的比例、恢复预测的校准、分组覆盖与不确定性，不只看总体准确率。
离线只看到原规则采取的动作；不能据此证明换站或早断开一定更好。
如果原规则提前结束了观察，仅靠统计方法也不能恢复其未发生的结果。

### D. 影子运行，再谈有限接管

以后单独实现影子模式：只记模型建议、概率、模型版本和当时特征，不执行。
模型文件需版本化，保留原规则作为回退；加载或预测失败就完全走原规则。

上线条件留给实际数据决定，但至少要满足：

- 多个后续时间段没有明显退化，不只是在训练集上好看。
- 对常用分组比简单基线有收益；没覆盖的分组继续原规则。
- 已有模拟上游验过慢首字、推理/工具增量、仅心跳、停顿后恢复、提前完成、
  断流、取消、写盘失败及正常长请求。
- 先建议、再显式授权小范围执行；需要实验时使用模拟服务或另外授权的真实流量，
  不默认延长现有等待、不偷偷多发请求增加费用。

模型不能越过的限制：

- 用户是否允许自动换候选/模型。
- 请求是否可安全重放、是否涉及状态和工具副作用。
- 响应是否已经向下游提交；不能在输出中途偷偷拼接另一个模型的新回答。
- 协议、能力、模型身份、时间、次数和费用预算。
- 人工取消优先，关闭模型或回退原规则应立即可用。

采集中的 `stateful` 和 `can_failover` 只是当前代码的观测字段，
不是对重放安全的完整证明。任何学习策略实际执行前，应重新审查现有重试入口。

### E. 路由学习与持续更新留在最后

前面的恢复预测验证有用后，再独立考虑候选排序。
需要额外记录决策时的完整候选可用性、选中概率、策略版本和成本反馈；
当前确定性规则日志没有这些反事实条件，不能直接做无偏的离线 Bandit 策略评估。

自动启用降级、模仿人工切站、在线学习、强化学习都尚未实现。
人工原因录入、最终客户端任务反馈、跨客户端重试关联也在这一阶段另行设计。
没有必要为了“可能以后会用到”现在先建训练平台、特征服务或常驻模型进程。

## 4. 代码入口与维护约定

- `gateway/learning.py`：有界记录器、事件窗口、写入/轮转、请求生命周期收尾。
- `gateway/proxy.py`：只在已有动作边界添加观测，不参与选择。
- `gateway/protocols.py`：SSE 元数据回调；回调失败不改变现有结束判定或流字节。
- `gateway/app.py`：采集器随应用启动/退出；只读状态接口。
- `dev/learning-report.py`：独立只读汇总；没有导入网关或打开配置数据库。
- `tests/test_learning.py`：隔离临时目录和假上游，检查关联、标签、隐私、限量与失败旁路。

修改格式时提升 `SCHEMA_VERSION`，汇总/训练程序显式处理或拒绝旧格式。
修改调度语义时更新 `POLICY_VERSION`，不要把不同时期的规则当成同一个策略。
本轮不新增 Python 依赖、不做数据库迁移、不修改前端、不改变正在运行的正式服务配置。
